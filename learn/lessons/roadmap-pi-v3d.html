Six lessons, one draw

  1. Why would the GPU need to decide anything?

    Predict the colors above, then inspect the captured row. Draw the three edges through the grid and test the two centers. This calculation is rasterization.

    Two figures and the hardware detail

    Where is our pair in the 64 × 64 frame? Which side of each edge does each center occupy? Zoom from the frame into the pair. On row 32 the centers are at x = 19.5 and 20.5, and the left edge crosses at 19.75. Connect those coordinates to the vertex record, which stores positions in sixteenths of a pixel.

    Packed vertex coordinates · Independent coverage check

  2. “Like instruction + input” — how does the driver start the GPU?

    Start at your Mac. Find the ARM CPU running Gabix, the VideoCore processor running Pi firmware, V3D and shared RAM on a map of the board. Follow one Wi-Fi request to the Rust function that reads the graphics hardware’s ID.

    Three figures and the hardware detail

    Where does the probe run? Who supplies the four ID bytes? Which register write starts the triangle’s blue background? Step through the upload, the optional mailbox power request and the ARM load from V3D. Then follow a color into a command list in RAM and watch V3D read it.

    Firmware domain 11 · Identification read · Submitting the addresses

  3. What extra work turns the clear into a triangle?

    Compare the two runs with the same blue background. Pause after binning and predict what the GPU has written so far. Then follow the render command that uses that result.

    Two figures and the hardware detail

    What does the binning thread leave in RAM? Decode the draw packet specifying three consecutive vertices and follow the primitive into the list for tile (0, 0). What reads that list? The render thread clears its tile, follows a branch to that list, and stores the tile. This experiment fits in one tile. The clear-only run skips binning and replaces the branch with five no-operation bytes.

    Binning packets · Render branch and store · Clear-only change · Linux VC4 render lists

  4. If the color comes from my input, what does the shader do?

    Keep the vertices and background fixed. Change only the foreground input, predict which of our two pixels will change, and draw again. Follow that color into one executed instruction.

    Two figures and the hardware detail

    What does the rasterizer hand to the shader processor? Zoom out from our edge to a 2 × 2 group of pixels and the coverage mask. V3D can group up to four of these groups for the Quad Processing Unit (QPU). What does the QPU write? Step through the shader loading the packed color into register r3, waiting for tile-buffer access and writing the color.

    Foreground input · QPU instructions · Broadcom architecture guide, sections 5–6

  5. “There must be some memory mapping?” Which address does each chip use?

    Inspect a real symptom from bring-up. The ARM changed the shader color, yet the returned triangle kept its previous color. Predict what each processor would read, then replay the working copy.

    Three figures and the hardware detail

    Where do the vertices, shader and finished pixels live? Give each region a stable place on a RAM map. Which address goes into a GPU command? Trace a buffer’s ARM address and VideoCore bus address to the intended storage. How does the new shader reach the QPU? Follow DMA channel 5 copying the instruction bytes from the source to the executable copy through the VideoCore-coherent alias. Mark the two copies and their addresses separately.

    RAM layout · Shader record · DMA source and destination · Board observation

  6. When is it safe to send the finished pixels to my Mac?

    Predict the first step where the ARM can read the new gold pixel. Then find its four bytes in the Mac’s file. At row 32, column 20 the byte offset is 4 × (32 × 64 + 20) = 8272.

    Two figures and the hardware detail

    When does the finished tile reach RAM? Step from the tile-store packet to the change in the completed-frame counter, then discard the ARM’s old cached pixels. How does byte 8272 reach the Mac? Follow it through the probe output and the 512-byte result chunk beginning at offset 8192. Finish by tracing that pixel from the three vertices to the file without the diagram.

    Tile store · Counter check · Cache and copy · Reading result chunks
