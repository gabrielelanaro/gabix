Nonblocking Socket Quick Reference

Receive contracts, readiness, and the queue ownership path.

Empty receive queue

Blocking recvfrom
Sleeps until a datagram or an error becomes available.
Nonblocking recvfrom
Returns immediately with EAGAIN or EWOULDBLOCK.

Ownership and observation

fd → process FD table → UDP socket → receive queue

The socket owns queued datagrams. A readiness implementation resolves the FD and observes whether an operation on that queue can make progress.

Readiness interfaces

select
Bit sets of descriptors; portable, with descriptor-count constraints.
poll
Array of descriptor/event records; a compact first target for mini-os.
epoll
Linux interest set and ready list designed for large, changing descriptor sets.

Event-loop rule

wait for readable descriptors
for each ready fd:
    receive until EAGAIN
    process each datagram
wait again

Keep descriptors nonblocking because readiness describes current state and may become stale before the receive call.

Two readiness layers

Device work
Polling or interrupts tell the kernel that the NIC has frames.
Socket work
Socket readiness tells user space that a syscall can make progress.

NIC → driver → protocol stack → socket queue → readiness waiter

mini-os implementation status

  1. Implemented: SOCK_NONBLOCK and empty-queue EAGAIN.
  2. Implemented: read-only poll over UDP socket queues.
  3. Implemented: atomic queue check plus waiter registration.
  4. Verified: ring-3 event loop over UDP ports 5555 and 7777.
  5. Future: finite timeouts, more event types, select, epoll, and interrupt-driven device receive.
