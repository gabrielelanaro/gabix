How mini-os opens a TCP connection

The kernel opens one TCP connection and receives one response byte.

A user-mode process needs a reliable byte stream to send a DNS query and read its response. This tour follows the kernel as it connects to slirp’s DNS server, exchanges the three TCP handshake segments, sends a 31-byte DNS-over-TCP query, and returns the first response byte. The implementation stores the sequence and acknowledgment positions required for this exchange. Retransmission and sliding-window flow control are separate work.

Background

The receive path processes a packet in three stages. The Ethernet driver supplies a frame. The IPv4 code reads the protocol field and passes protocol 6 to TCP. The TCP code reads the segment header and updates the connection state.

A TCP segment has a minimum 20-byte header. The header contains source and destination ports, sequence and acknowledgment numbers, flags, a receive window, and a checksum. TCP options can extend the header. The data-offset field gives the header length, so the parser can locate the payload.

UDP state

A port, a datagram queue, and a waiter. Each datagram stands alone.

TCP state

A fixed peer, connection state, byte positions, receive window, buffered bytes, and waiters.

Why sequence numbers matter

Sequence N identifies a byte position. An ACK of N says “the next byte I need is N.”

TCP Control BlockA TCP Control Block (TCB) stores one connection’s IP addresses, ports, state, sequence positions, receive window, buffered bytes, and blocked process identifiers. This implementation stores one TCB in a global slot.

Intuition

Each endpoint chooses the first sequence number for its outbound byte stream. A SYN consumes one sequence number even though it carries no payload. Each payload byte consumes one sequence number. The handshake establishes one send position and one receive position for each endpoint.

1 · client → server
SYN, seq = x
“Start my stream at x.”
2 · server → client
SYN + ACK, seq = y, ack = x + 1
“My stream starts at y; I received your SYN.”
3 · client → server
ACK, seq = x + 1, ack = y + 1
“I received your SYN-ACK.”

After message three, the client stores x + 1 as its next send position and y + 1 as its next receive position. The server stores the corresponding positions. A payload segment starts at the sender’s current send position.

The parser validates the complete segment before returning its payload slice. The builder adds a four-byte Maximum Segment Size (MSS) option to SYN packets.

Code walkthrough

1. Parse and build variable-length segments

TcpSegment::parse rejects input shorter than 20 bytes and segments with an invalid checksum. It reads the data-offset field, rejects a header shorter than 20 bytes or longer than the segment, and returns the bytes after the header as the payload. write_segment writes a 24-byte header for SYN and a 20-byte header for other segments, then computes the checksum over the IPv4 pseudo-header and TCP bytes.

let header_len = ((bytes[12] >> 4) as usize) * 4;
if header_len < 20 || header_len > bytes.len() { return None; }
if tcp_checksum(src_ip, dst_ip, bytes) != 0 { return None; }

2. Start the active open

active_open creates the TCB in SynSent. It sets send_next and send_unacked to the Initial Sequence Number (ISN), builds a SYN, stores the TCB, and returns the segment for transmission.

let tcb = TcpControlBlock {
    endpoints, state: TcpState::SynSent,
    send_next: isn, send_unacked: isn,
    recv_next: 0, recv_window: 4096,
    receive: Vec::new(), connect_waiter: None, recv_waiter: None,
};

3. Validate the SYN-ACK

The receive path checks the checksum and compares the segment’s source and destination addresses and ports with the TCB. In SynSent, it accepts a SYN+ACK only when its acknowledgment equals send_next + 1. The code advances send_next past the client SYN, sets recv_next to the server sequence number plus one, builds the final ACK, changes the state to Established, and wakes the process blocked in connect.

The network worker calls tcp::receive for protocol 6. When that function returns an Outbound, the worker passes its bytes to the existing IPv4 and Ethernet transmit path. TCP updates the TCB; the network worker transmits the returned segment.

5. Send and receive application bytes

send_data returns no segment unless the TCB is Established. It builds a PSH+ACK segment at the current send position and advances send_next by the payload length. For an in-order received payload, the receive path appends the bytes to the buffer, advances recv_next by the payload length, builds an ACK, and wakes a process waiting in recv.

let seq = tcb.send_next;
let outbound = build(tcb, FLAG_PSH | FLAG_ACK, payload)?;
tcb.send_next = tcb.send_next.wrapping_add(payload.len() as u32);

Context: the complete active-open function

The earlier summary names the important assignments. This is the complete active_open function from src/net/tcp.rs. It constructs the TCB before sending anything, builds the SYN from that same state, records the TCB in the global slot, and returns the segment to the syscall layer.

pub fn active_open(endpoints: Endpoints, isn: u32) -> Option<Outbound> {
    let tcb = TcpControlBlock {
        endpoints,
        state: TcpState::SynSent,
        send_next: isn,
        send_unacked: isn,
        recv_next: 0,
        recv_window: 4096,
        receive: Vec::new(),
        connect_waiter: None,
        recv_waiter: None,
    };
    let outbound = build(&tcb, FLAG_SYN, &[])?;
    println!("[tcp] state CLOSED -> SYN_SENT; SYN seq={}", isn);
    *TCB.lock() = Some(tcb);
    Some(outbound)
}

Context: the complete receive function

receive contains both receive paths used by the tour. The first branch accepts the SYN-ACK. The second branch runs after establishment and queues an in-order payload. The same function returns the ACK segment to the network worker.

pub fn receive(src_ip: [u8; 4], dst_ip: [u8; 4], bytes: &[u8]) -> Option<Outbound> {
    let segment = TcpSegment::parse(bytes, src_ip, dst_ip)?;
    let mut slot = TCB.lock();
    let tcb = slot.as_mut()?;
    if src_ip != tcb.endpoints.remote_ip || dst_ip != tcb.endpoints.local_ip
        || segment.header.src_port != tcb.endpoints.remote_port
        || segment.header.dst_port != tcb.endpoints.local_port { return None; }

    if tcb.state == TcpState::SynSent
        && segment.header.flags & (FLAG_SYN | FLAG_ACK) == (FLAG_SYN | FLAG_ACK)
        && segment.header.acknowledgment == tcb.send_next.wrapping_add(1) {
        tcb.send_next = tcb.send_next.wrapping_add(1);
        tcb.send_unacked = tcb.send_next;
        tcb.recv_next = segment.header.sequence.wrapping_add(1);
        tcb.recv_window = segment.header.window;
        println!("[tcp] SYN-ACK seq={} ack={} matched",
            segment.header.sequence, segment.header.acknowledgment);
        let outbound = build(tcb, FLAG_ACK, &[])?;
        tcb.state = TcpState::Established;
        println!("[tcp] final ACK seq={} ack={}; state SYN_SENT -> ESTABLISHED",
            tcb.send_next, tcb.recv_next);
        if let Some(pid) = tcb.connect_waiter.take() { crate::task::wake(pid); }
        return Some(outbound);
    }
    if tcb.state != TcpState::Established { return None; }
    if segment.header.acknowledgment > tcb.send_unacked
        && segment.header.acknowledgment <= tcb.send_next {
        tcb.send_unacked = segment.header.acknowledgment;
    }
    if !segment.payload.is_empty() && segment.header.sequence == tcb.recv_next {
        tcb.receive.extend_from_slice(segment.payload);
        tcb.recv_next = tcb.recv_next.wrapping_add(segment.payload.len() as u32);
        println!("[tcp] data rx len={} next_ack={}",
            segment.payload.len(), tcb.recv_next);
        let outbound = build(tcb, FLAG_ACK, &[])?;
        if let Some(pid) = tcb.recv_waiter.take() { crate::task::wake(pid); }
        return Some(outbound);
    }
    None
}

Context: the syscall-to-network call path

The complete syscall function shows where the returned SYN goes. active_open returns a segment; transmit_tcp sends it; the loop blocks the user process until receive wakes it after the final ACK is built.

fn sys_net_tcp_connect() -> u64 {
    let local_ip = net::source_ip();
    if local_ip == [0; 4] { return u64::MAX; }
    let isn = (crate::interrupts::TICKS.load(Ordering::Relaxed) as u32)
        .wrapping_mul(1103515245).wrapping_add(0x31c0_ffee);
    let Some(syn) = net::tcp::active_open(net::tcp::Endpoints {
        local_ip, remote_ip: [10, 0, 2, 3], local_port: 49152, remote_port: 53,
    }, isn) else { return u64::MAX };
    if !transmit_tcp(syn) { return u64::MAX; }
    while net::tcp::state() != net::tcp::TcpState::Established {
        crate::task::block_current_if(|pid| net::tcp::register_connect_waiter(pid));
        crate::task::yield_now();
    }
    0
}

Boundaries of this change

This code stores connection state and advances byte positions for one active connection. It has no retransmission timer, round-trip-time measurement, sliding window, passive open, connection teardown, or support for multiple simultaneous TCBs. The receive path accepts only a payload whose sequence number equals recv_next. Out-of-order recovery belongs to the reliable-stream lesson.
