DHCP and runtime network configuration

From 0.0.0.0 to an installed DHCP lease.

When the kernel boots, its IP address is 0.0.0.0. It cannot send IP packets in that state: every IPv4 packet carries a source address, and 0.0.0.0 is not a usable source on the wire. DHCP (Dynamic Host Configuration Protocol) is how a host asks the network for an address — the host broadcasts a request, a server replies with an offered address, and the host holds that address for a fixed period called a lease.

This tour follows one exchange end to end. A ring-3 client program runs the four-message DORA exchange (DISCOVER, OFFER, REQUEST, ACK) with QEMU’s built-in DHCP server (slirp, at 10.0.2.2), then installs the leased address into kernel state through the net_configure syscall. The five sections below walk through this exchange: where the lease lives, how a broadcast packet reaches the wire, what the client sends and receives, how the syscall installs the result, and the serial output that proves it worked.

1. Kernel configuration state

NetworkConfig stores the address, subnet mask, gateway, DNS server, and lease duration. source_ip() returns 0.0.0.0 while this state is empty.

src/net/mod.rs — runtime configuration
static CONFIG: IrqMutex<Option<NetworkConfig>> = IrqMutex::new(None);

pub fn source_ip() -> [u8; 4] {
    config().map(|value| value.address).unwrap_or([0; 4])
}

2. Broadcast before configuration

send_ipv4_packet maps 255.255.255.255 directly to the Ethernet broadcast address. This path skips ARP because no host owns the limited-broadcast IPv4 address.

src/virtio.rs — DHCP transmit path
let broadcast = dst_ip == [255; 4];
let next_hop_mac = if broadcast {
    [0xff; 6]
} else if let Some(mac) = arp::lookup(next_hop_ip) {
    mac
} else {
    self.send_arp_request(next_hop_ip);
    return None;
};

3. The ring-3 exchange

The client reads the device MAC address, binds UDP port 68, and runs the four-message exchange. The parser verifies the magic cookie and transaction identifier before reading type-length-value options.

tests/fixtures/dhcp.rs — DORA sequence
send(DHCPDISCOVER);
let offer = receive(DHCPOFFER);
send(DHCPREQUEST, offer.address, offer.server);
let ack = receive(DHCPACK);
net_configure(ack);

4. Syscall boundary

Syscall 904 operation 0 returns the MAC address. Operation 1 validates the required address and mask fields, copies the lease into kernel state, and prints the installed values.

src/syscall.rs — configuration installation
net::configure(net::NetworkConfig {
    address: config.address,
    subnet_mask: config.subnet_mask,
    gateway: config.gateway,
    dns: config.dns,
    lease_seconds: config.lease_seconds,
});

5. End-to-end proof

Expected serial output
[dhcp-client] DISCOVER
[dhcp-client] OFFER
[dhcp-client] REQUEST
[dhcp-client] ACK
[dhcp] configured address=10.0.2.15 ... gateway=10.0.2.2 ...
[dhcp-client] lease 10.0.2.15 installed from ring 3
