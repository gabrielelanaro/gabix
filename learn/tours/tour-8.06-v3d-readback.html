Frame readback in Gabix

Follow one completion indication, then follow one four-byte pixel across two separate buffers and a file.

Wait and take ownership

The render counter must change. The cache helper issues an ARM data-cache invalidate by address followed by a synchronization barrier. The copy then writes the finished frame into output RAM owned by the runner.

Reassemble the file

The caller learns the byte count from RUN, then uses the number of bytes already received as its next offset. The Pi caps each reply at the available reply space. The host checks each chunk length and appends it.

Check against the board

The frame is 16,384 bytes, so a complete read takes 32 result chunks of 512 bytes. Chunk 17 begins at offset 8192, counting chunks from one. Its bytes 80–83 contain pixel (20, 32). Frame size · Pixel offset
