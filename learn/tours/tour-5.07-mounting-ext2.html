Code Tour — Mount ext2 via Filesystem Trait

The biggest architectural change since the project started. VFS becomes filesystem-agnostic. Old hardcoded inodes deleted. ext2 walks on demand.

Steps done 14.1 – 14.4 (complete) Commit 81e58fc

Lesson 14 is the keystone of the filesystem phase. Everything before it (Lessons 5–13) built the pieces — PCI, virtio, virtqueues, block layer, ext2 parser. Lesson 14 connects them to the VFS via a trait, making the kernel genuinely read files from disk.

Two decisions shaped this lesson: (1) on-demand, not pre-load — the user pushed back hard on loading everything into RAM; (2) Filesystem trait, not globals — the user wanted the clean abstraction. Both were the right call.

14.1Add files to the disk image

Files: scripts/make-disk.sh

debugfs writes files into the ext2 filesystem without mounting. Pipes commands via stdin with an explicit quit to exit cleanly.

# Two files: hello.txt + secret.txt
printf 'write %s /hello.txt\nwrite %s /secret.txt\nquit\n' \
    "$HELLO_SRC" "$SECRET_SRC" | debugfs -w disk.img

After this, the disk has 5 root entries: ., .., lost+found, hello.txt (inode 12), secret.txt (inode 13).

14.2Filesystem trait + Ext2 struct + impl

Files: src/fs.rs (+trait), src/ext2.rs (+struct, +impl)
src/fs.rs— the trait (4 methods)
pub trait Filesystem {
    fn inode_kind(&self, ino: u64) -> Option<InodeKind>;
    fn lookup(&self, dir_ino: u64, name: &str) -> Option<u64>;
    fn list_dir(&self, dir_ino: u64) -> Option<Vec<(String, u64)>>;
    fn read_file(&self, ino: u64) -> Option<Vec<u8>>;
}
src/ext2.rs— Ext2 struct owns the device + parsed metadata
pub struct Ext2 {
    dev: Mutex<VirtioBlk>,
    sb: Superblock,
    bgd0: BlockGroupDescriptor,
}

impl Filesystem for Ext2 {
    fn read_file(&self, ino: u64) -> Option<Vec<u8>> {
        let inode = self.read_inode(ino as u32);
        if !inode.is_reg() { return None; }
        Some(self.read_file_data(&inode))
    }
    // ... inode_kind, lookup, list_dir similarly
}

The old free-function readers (read_inode(dev, sb, bgd, ino)) are now methods on Ext2 (self.read_inode(ino)). The with_dev helper locks the Mutex internally.

14.3resolve_path walks ext2 on demand

Files: src/fs.rs
src/fs.rs— the new resolve_path (no ROOT_INODE reference)
pub fn resolve_path(path: &str) -> Option<Arc<Inode>> {
    let fs = MOUNTED_FS.lock();
    let fs = fs.as_ref()?;

    let mut current_ino: u64 = 2; // ext2 root
    for component in path.split('/').filter(|c| !c.is_empty()) {
        let kind = fs.inode_kind(current_ino)?;
        if kind != InodeKind::Dir { return None; }
        current_ino = fs.lookup(current_ino, component)?;
    }

    // Cache check
    if let Some(cached) = REGISTRY.lock().get(&current_ino) {
        return Some(cached.clone());
    }

    // Cache miss: build from ext2, cache, return
    let kind = fs.inode_kind(current_ino)?;
    let data = match kind {
        Dir => { /* encode list_dir as fs.rs dirents */ }
        File => fs.read_file(current_ino)?,
    };

}

What was removed

  • ROOT_INODE lazy_static (hardcoded in-memory tree from Lessons 1-3)
  • HARDCODED_INODE lazy_static (alias for hello.txt)
  • HELLO_INO / SECRET_INO constants
  • Lesson 3.3 filesystem setup test (tested ROOT_INODE)
  • Lesson 3.4 path resolution test (tested resolve_path against in-memory tree)
  • Lesson 3.6 multiple files test
  • Verbose per-I/O println! calls in virtio.rs (submit_chain, kick, poll, desc chain, buffer alloc)

The old hardcoded inodes used inode numbers 1-3 which collided with ext2's numbering (root=2). Deleting them fixed the collision — the root cause of a mysterious bug where resolve_path("/") returned a File instead of a Dir.
