From FD 0 to a sleeping UDP echo server

Follow one datagram through the socket object, receive queue, scheduler, network worker, and ring-3 reply.

Lesson 25 delivered UDP to a fixed kernel handler. Lesson 26 gives the endpoint to a user program. The kernel creates a socket object, names it with an FD, queues incoming messages, blocks the process, and wakes it when a message arrives.

Read the tour in execution order

Use the walk first. Each implementation section then shows the code owner for that stage.

Execution walk · stage 1 of 8

1 · The kernel starts the network worker

main installs the virtio-net device and, for the UDP test, spawns a kernel task that keeps polling RX while user programs sleep.

2 · User space creates fd 0

socket(AF_INET, SOCK_DGRAM, 0) creates an Arc<UdpSocket> and inserts it into the current process’s lowest free FD slot.

3 · User space binds port 5555

bind(0, 10.0.2.15:5555) records the local port and inserts a weak reference into the global port table.

4 · recvfrom finds an empty queue

The syscall pops nothing, registers PID 0 as the socket waiter, marks the current task Blocked, and yields. The user program sleeps inside one syscall.

5 · The worker receives the host datagram

The worker polls a virtio completion, parses Ethernet, validates IPv4, parses UDP protocol 17, and copies the payload into an owned packet value.

6 · Delivery fills the socket queue

The port table finds port 5555. deliver pushes a datagram containing payload and sender endpoint, takes the waiter PID, and calls wake.

7 · recvfrom resumes

The scheduler runs PID 0 again. The syscall pops one datagram, copies its bytes and sender endpoint into user buffers, and returns the byte count.

8 · sendto returns the reply

The user program supplies the sender endpoint returned by recvfrom. The kernel builds UDP/IPv4/Ethernet bytes and sends them through virtio TX.

26.1An FD can name a socket

Files: src/fs.rs, src/process.rs

The existing VFS already gives each process an FD table. The implementation changes the table value from “file only” to an enum that can hold a file or a socket. The integer interface stays process-local.

src/fs.rsone FD table, two object kinds
pub enum OpenObject {
    File(Arc<File>),
    Socket(Arc<UdpSocket>),
}

pub fn open_socket(&mut self, socket: Arc<UdpSocket>) -> u64 {
    self.open_object(OpenObject::Socket(socket))
}
What does fd 0 contain?

The number 0 indexes the current process’s table. The table slot contains an OpenObject::Socket, which owns an Arc pointing to the UDP socket object.

26.2The socket owns queue state

Files: src/net/socket.rs, src/net/mod.rs

UdpSocket stores the state that belongs to one user-visible endpoint. The receive queue owns complete datagrams, including the sender needed for the echo reply.

src/net/socket.rssocket state and global port lookup
pub struct Datagram {
    pub sender: Endpoint,
    pub payload: Vec<u8>,
}

struct State {
    port: Option<u16>,
    queue: VecDeque<Datagram>,
    waiter: Option<Pid>,
}

static PORTS: Mutex<BTreeMap<u16, Weak<UdpSocket>>>;

The port map uses weak references. The process FD table owns the strong reference that keeps the socket alive. Routing metadata can disappear after the last FD closes.

Which object owns the message bytes?

The socket’s VecDeque<Datagram> owns them. The port table only finds the socket, and the FD table only provides access to it.

26.3bind gives the socket a local port

Files: src/syscall.rs, tests/fixtures/udp_echo.rs

The user fixture builds a small IPv4 address structure. The kernel validates it, looks up fd 0 as a socket, records port 5555, and publishes the socket in PORTS.

src/syscall.rsvalidate the address and bind the typed FD
fn sys_bind(fd: u64, addr: u64, addr_len: u64) -> u64 {
    let Some(endpoint) = read_sockaddr(addr, addr_len) else {
        return u64::MAX;
    };
    let Some(socket) = get_socket(fd) else {
        return u64::MAX;
    };
    if socket.bind(endpoint.port).is_ok() { 0 } else { u64::MAX }
}

Lesson 26 binds the server. A client can later let the kernel choose an ephemeral source port; this fixture needs a known destination port so QEMU host forwarding can find it.

26.4The syscall entry preserves six arguments

Files: src/syscall.rs, tests/fixtures/udp_echo.rs

Linux-style recvfrom and sendto need six arguments. The syscall entry saves registers r10, r8, and r9 before the handler uses them for kernel work.

syscall_entrysave arguments 4–6 before changing register state
mov [{arg4_save}], r10
mov [{arg5_save}], r8
mov [{arg6_save}], r9

; later, the Rust handler reads the saved values
let arg4 = SYSCALL_ARG4.load(Ordering::Relaxed);
let arg5 = SYSCALL_ARG5.load(Ordering::Relaxed);
let arg6 = SYSCALL_ARG6.load(Ordering::Relaxed);

The fixture mirrors that ABI: fd, buffer, length, flags, address pointer, and address-length pointer travel in rdi, rsi, rdx, r10, r8, and r9.

Why save r10 before switching stacks?

The entry code needs scratch registers while moving from the user stack to the kernel stack. Saving the incoming value first preserves the fourth user argument.

26.5recvfrom parks the current task

Files: src/syscall.rs, src/task.rs

sys_recvfrom first tries the queue. An empty queue enters a short interrupt-disabled region that checks the queue again, records the waiter, and marks the task blocked. That ordering closes the lost-wakeup window.

sys_recvfrompop, atomically register, block, yield, retry
loop {
    if let Some(datagram) = socket.pop() {
        // copy payload and sender to validated user buffers
        return count as u64;
    }

    let should_block = without_interrupts(|| {
        if socket.register_waiter_if_empty(current_pid()) {
            block_current();
            true
        } else { false }
    });
    if should_block { yield_now(); }
}
queue check → register waiter → Blocked → yield
                                           ↑
                           must be one atomic decision

A packet can arrive between a queue check and waiter registration. Disabling interrupts around both operations lets the single-CPU kernel make one indivisible decision.

26.6The network worker delivers and wakes

Files: src/virtio.rs, src/net/udp.rs, src/net/socket.rs

The network worker keeps polling the device while the echo task is blocked. The RX dispatcher turns the frame into an owned UdpPacket, then hands the destination port and sender endpoint to the socket layer.

network_workerpoll RX, then yield so blocked work can wake
pub unsafe extern "C" fn network_worker() {
    loop {
        let _ = with_net_device(|device| device.poll_rx());
        crate::task::yield_now();
    }
}
deliverqueue the complete message and wake its waiter
pub fn deliver(port: u16, sender: Endpoint, payload: &[u8]) -> bool {
    let socket = PORTS.lock().get(&port).and_then(Weak::upgrade);
    let waiter = { /* push Datagram, take waiter PID */ };
    if let Some(pid) = waiter { crate::task::wake(pid); }
    true
}

The socket lock protects queue state. The scheduler lock protects task state. Delivery releases the socket state before calling wake, so the two ownership domains stay separate.

26.7sendto rebuilds the reply from the returned endpoint

Files: src/syscall.rs, src/virtio.rs, src/net/udp.rs

The user program keeps the sender address written by recvfrom. sendto validates that destination, reads the user payload, and passes the local bound port plus destination endpoint to the existing UDP transmit path.

sys_sendtoFD lookup, user buffer, destination, existing TX path
let Some(socket) = get_socket(fd) else {
    return u64::MAX;
};
let Some(src_port) = socket.local_port() else {
    return u64::MAX;
};
let payload = unsafe { slice::from_raw_parts(buf as *const u8, len as usize) };

with_net_device(|device| device.send_udp(dst.ip, dst.port, src_port, payload))

The reply route reverses the endpoint pair: guest 10.0.2.15:5555 becomes the source, and the original sender becomes the destination.

Retrieve the ownership chain

A datagram arrives for port 5555 while PID 0 sleeps in recvfrom. Name the object that maps fd 0, the object that maps port 5555, the object that owns the bytes, and the function that wakes PID 0.

Answer

The process FD table maps fd 0 to OpenObject::Socket(Arc<UdpSocket>). PORTS maps port 5555 to a weak socket reference. The socket’s queue owns the Datagram. deliver calls task::wake(pid).

Primary sources

socket(2), bind(2), recvfrom(2), and sendto(2) define the Linux syscall contracts. RFC 1122 §4.1.4 describes the UDP/application interface.
