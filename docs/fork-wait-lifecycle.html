Fork + Wait, end to end

How mini-os clones a running process, gives the child its own private memory, schedules both, and lets the parent block until the child exits. Built across six slices (4.4.a – 4.4.f). This page walks through the whole mechanism.

5 syscalls 2 address spaces 4 levels of page tables 1 CPU

01 The big picture

Two syscalls cooperate to give us process management. Each one is simple on its own; the magic is in how they interact via the scheduler.

fork SYS_FORK (57)

Clone the calling process. The kernel snapshots the parent's user-mode register state, deep-clones its page table (independent frames at every level, private copies of every user page), and creates a new task. The new task runs the same code with a different return value.

Parent sees: child's PID in RAX.
Child sees: 0 in RAX.

wait SYS_WAIT4 (61)

The parent asks the kernel to block until any child exits, then reap it. If a child is already a Zombie, return immediately. If children exist but none have exited, mark self Blocked and yield — the next child to exit will wake the parent.

Returns: the reaped child's PID, with the exit code written to a user pointer.

02 Address space basics

Each process has its own page-table tree — a 4-level walk from PML4 down to a 4 KB frame. Virtual addresses translate per-process. Real Linux splits this cleanly: kernel in entries 256–511, user in entries 0–255. Ours doesn't.

linux The clean split

Linux links its kernel at 0xFFFF_8000_0000_0000 and above — PML4 entries 256–511. Every process's upper-half entries point at the same shared kernel subtree. Adding a kernel mapping automatically appears in all processes. Clean.

ours The low-address wart

Our bootloader loaded the kernel at 0x200000, VGA at 0xb8000, heap at 0x4444_4444_0000 — all in entries 0–255, mixed in with user memory. "Share the kernel half" doesn't work cleanly.

Workaround: deep-clone the whole tree, share only kernel data frames (entries without USER_ACCESSIBLE).

① Saved state snapshot

Globals in syscall.rs capture user RIP/RSP/RFLAGS + 6 callee-saved regs at the moment of the syscall. sys_fork reads them ONCE and passes them through. The globals can be overwritten by future syscalls without affecting the child.

② Per-task syscall stack

Without this, parent and child collide on the shared syscall stack. Each task gets its own 16 KB stack at SYSCALL_STACK_BOTTOM + (id+1) * STACK_SIZE. yield_now updates KERNEL_RSP on every switch.

③ Deep PT clone

Walks PML4 → PDPT → PD → PT, allocating fresh frames at each level. User pages get a private 4 KB copy; kernel pages share the frame. Fixes the shared-PT bug where unmapping in child also unmapped in parent.

04 Deep page-table clone

Each level of the child's page table is a fresh frame. At the leaf level (PT), user pages get private copies; kernel pages are shared via direct entry copy. The two trees are completely independent below the PML4.

↓

Kernel pages — entries without the USER_ACCESSIBLE flag — skip the leaf copy: their PT entry is copied as-is, sharing the physical frame. Both processes see the same kernel bytes at the same virtual addresses, but neither can accidentally break the other's user pages.

05 The child's first run

When the scheduler eventually picks the child, switch() pops the callee-saved area and rets into fork_trampoline. The trampoline sets RAX=0 and sysretqs to user mode.

Why naked asm?

Initial attempt used inline asm! with in(reg) constraints. Compiler register allocation clobbered values mid-asm (RCX ended up 0, sysretq jumped to address 0). Converting to naked_asm! — every mov explicit, every register pinned — fixed it.

Why fixed stack offsets?

Saved user state lives on the child's kernel stack at stack_top - 64/-72/-80 — below the callee-saved area that switch() pops. Reads via [rsp - N] after the ret. No global state, so multiple forks can't overwrite each other.

08 Ours vs Linux

We use the same ideas as Linux but with extra workarounds because our kernel isn't linked at high addresses. The right-hand column shows what we'd do if we relinked.

Kernel address range Low: 0x200000, heap 0x4444_…, all in PML4 entries 0–255 High: 0xFFFF_8000_… and above, PML4 entries 256–511
PML4 entry-level split No clean split — kernel and user share entries 0–255 Entries 256–511 shared kernel subtree; 0–255 per-process user

User-page copy at fork Eager: allocate fresh frame + memcpy 4 KB for every user page Copy-on-write: shared until first write, then page-fault handler copies
Saved user state Globals + snapshot at fork time, written to child kernel stack at fixed offsets pt_regs struct on the kernel stack at a known layout

09 Known limitations

Working fork + wait, with these caveats. Most are deferred until the kernel is relinked at high addresses (the "real fix" that simplifies much of the above).

  • Kernel not at high addresses Forces deep-clone workarounds. Proper fix: relink kernel at 0xFFFF_8000_…, get the clean PML4-entry-level split for free. Documented as future work.
  • No copy-on-write fork eagerly copies every user page. Real Linux defers the copy until first write. Ours is correct, just expensive for big processes.
  • No resource cleanup Dead tasks' kernel stacks, syscall stacks, and address spaces (including the entire deep-cloned page table) all leak. Memory grows unboundedly with process count.
  • Test doesn't exercise blocking The simple test happens to hit the immediate-reap path (child exits before parent calls wait). The blocking logic is implemented but not run-time tested.
  • TSS.RSP0 is static Set once at boot to main's stack. If a child gets a timer interrupt in user mode, the interrupt context goes to main's stack. Works because main's stack is accessible in every AS, but Linux does this better.
  • No exec syscall Fork + wait give us process tree management but every child runs the same program as its parent. exec (load a different program into the current process) is the missing piece for a real shell.
