Reliable stream

Hold a copy of every byte sent. Resend what goes unconfirmed.

Primary spec RFC 9293 · RFC 6298 Linux counterpart net/ipv4/tcp_timer.c Proof 1 KB exchange with slirp DNS over TCP

A TCP socket promises the application that every byte written will arrive at the peer, in order, exactly once. Lesson 31 made that promise for one byte: the sender transmitted a byte, the receiver sent an ACK, the sender advanced its bookkeeping. The exchange worked because the segment arrived.

Real networks drop packets. A router under load discards a frame when its queue fills; a noisy cable corrupts a byte and the receiver's checksum fails; a busy receiver overflows its buffer and the segment vanishes. Neither sender nor receiver gets a notification. If TCP just sent bytes and hoped, a single dropped segment would break the stream: bytes after the gap would arrive, the application would see the gap, and the missing bytes would never come.

TCP keeps its promise by holding a copy of every byte sent, until the receiver confirms it arrived. Bytes that go unconfirmed for too long are sent again. The machinery has three pieces, built in this lesson: the retransmit queue (the held copies), the sliding window (how many bytes can be in flight at once), and the retransmission timer (how long counts as "too long", derived from measured round-trip time, with Karn's algorithm for handling retransmitted segments).

The cost of one byte at a time

Lesson 31 sent a single byte and waited for its ACK before doing anything else. This pattern is stop-and-wait. Every byte costs one full round-trip time (RTT). On a 100 ms link that caps throughput at 10 bytes per second.

Real TCP keeps many bytes in flight at once. While byte 100 is traveling toward the receiver, byte 200 is being prepared, byte 300 is queued behind it. Each byte still gets acknowledged, but the acknowledgments stream back alongside the data instead of blocking each successive send. The cap on in-flight bytes is the sliding window, covered below.

The retransmit queue

For every byte the sender has transmitted but not yet had acknowledged, it keeps a copy. The collection of held bytes, organized by segment, is the retransmit queue. Linux calls it sk_write_queue on struct sock. mini-os stores a Vec<TcpSegment> on the TCB.

When an ACK arrives with ack_number = N, every byte in the queue whose sequence is below N has been received. The sender removes those entries. If the queue is non-empty after the removal, the retransmit timer is restarted on the new oldest entry.

The sliding window

The sender tracks two positions on its outbound byte stream: send_unacked, the oldest byte still in flight, and send_next, the next byte to send. The bytes between them are in flight: transmitted, retained in memory, and awaiting an acknowledgment (ACK).

send_unacked send_next v v stream |======= in flight ======|=== can send ===|------------ | | | +-- window edge = send_unacked + send_window

The maximum distance the right edge can sit ahead of send_unacked is the send window:

send_window = min(advertised_window, congestion_window)
  • advertised_window comes from the window field in the most recent segment the receiver sent. It is the receiver's remaining buffer space. The receiver can shrink it to zero ("stop sending") when its application is slow to read.
  • congestion_window limits how much data the sender puts into the network. mini-os fixes this limit at four segments. A complete TCP implementation applies RFC 5681 slow start and congestion avoidance to adjust the limit after acknowledgments and loss.

When an ACK arrives and send_unacked advances, the window slides forward: bytes that were past the right edge become eligible for sending.

The retransmission timer

Each in-flight segment starts a timer when it is transmitted. If the timer fires before the segment's ACK arrives, the segment is resent.

The timer length is the RTO (Retransmission Timeout). Set it too short and the sender resends segments that are still in transit, wasting bandwidth. Set it too long and recovery from real loss is sluggish. The right value is a small multiple of the measured round-trip time.

Measuring round-trip time (RFC 6298)

Each time an ACK arrives for a segment that was sent exactly once, measure the time between send and ACK. This is one RTT sample.

From a stream of samples, maintain two running values:

SRTT = (7/8) * SRTT + (1/8) * sample RTTVAR = (3/4) * RTTVAR + (1/4) * |SRTT_old - sample| RTO = SRTT + max(G, K * RTTVAR) where K = 4

SRTT is the smoothed RTT: an exponential moving average that weights recent samples more heavily than old ones. RTTVAR is the smoothed mean deviation, a measure of how much RTT bounces around. G is the clock granularity, which for mini-os is the 100 Hz timer tick (10 ms). The initial value of RTO before any sample is taken is 1 second (RFC 6298 section 2.1). On the first sample, set SRTT = sample and RTTVAR = sample / 2.

Each time the sender retransmits, RTO doubles. This is exponential backoff (RFC 6298 section 2.5): a persistently lossy path slows the sender down instead of flooding it. The backoff resets to the computed RTO when a fresh ACK arrives for an unretransmitted segment.

Karn's algorithm

If a segment was retransmitted and an ACK for it later arrives, the ACK might be confirming the original transmission (which was slow) or the retransmit (which was faster). The sender cannot tell. Sampling RTT from that ambiguous ACK would feed a wrong value into SRTT.

Karn's algorithm (Phil Karn, 1987, originally for amateur packet radio) says: do not update SRTT or RTTVAR for any segment that has been retransmitted. Sample RTT only from segments that succeeded on their first transmission. The retransmit timer still uses the current RTO; the measurement is simply discarded for averaging purposes.

What to build in mini-os

Lesson 32 layers reliability on top of the Lesson 31 connection. The wire format is unchanged; the work is in the TCB and the per-connection timer.

32.1
Retransmit queue. Add retransmit_queue: Vec<RetransmitEntry> to the Transmission Control Block (TCB). Each entry stores the sequence number, flags, payload bytes, send tick, and retransmission marker. When an ACK arrives, remove every entry whose ending sequence is at or below the acknowledgment number.
32.2
Sliding window send. Replace Lesson 31's "send one byte" with a tcp_send(&buf) that loops: while send_next - send_unacked < send_window and the buffer still has bytes, build a segment of up to MSS bytes from send_next, transmit it, push it onto the retransmit queue, advance send_next. Use MSS 1460 and a fixed congestion window of four segments (skips RFC 5681).
32.3
RTT measurement. Add srtt_ms and rttvar_ms to the TCB, initialized to 1000 and 500. On each ACK for a segment that was transmitted exactly once, compute the sample RTT from the segment's sent_at timestamp, then update SRTT and RTTVAR per the RFC 6298 formulas above.
32.4
RTO and retransmit timer. Compute rto_ms = srtt_ms + max(10, 4 * rttvar_ms). Give the TCB a retransmit_deadline field set to now + rto_ms whenever the queue is non-empty. Each timer tick, check whether the deadline has passed. If it has, retransmit the oldest queue entry, double rto_ms, reset the deadline.
32.5
On ACK. Dequeue acknowledged segments. Restart the retransmit timer using the new oldest entry's sent_at if the queue is non-empty. Reset rto_ms to the computed value (cancelling backoff) if the ACK covers a segment that was not retransmitted.
32.6
End-to-end proof. Build with a 12-byte test Maximum Segment Size (MSS), so one 31-byte Domain Name System (DNS) query becomes three segments. Withhold the first data segment before virtio transmission and transmit the next two. The serial log must show the retransmission timeout (RTO) expire, the first segment transmit again, one cumulative ACK drain the queue, Karn's algorithm reject the ambiguous round-trip-time sample, and the DNS response reach ring 3.
Skipped on purpose

Slow start, congestion avoidance, fast retransmit, fast recovery (RFC 5681, RFC 5682). SACK (RFC 2018). Window scaling (RFC 7323). Timestamp options for RTTM. These all live in real TCP and are not built here. The Lesson 32 sender uses a fixed congestion window and recovers from loss only by timeout, not by duplicate-ACK counting. That is enough to deliver bytes reliably on a slirp link; a real network would warrant the rest.

Minigame — run the Retransmit Desk

Operate the sender this lesson builds. The application hands you a 96-byte file for 10.0.2.3:53. It leaves in 12-byte segments — the test MSS of step 32.6 — over a link with a 1000 ms round-trip time that drops one segment without telling either side. Your held copies, the window edge, and the RTO bar are how you find out.

  • SEND the next segment while in-flight bytes fit inside send_window = min(advertised, congestion). Sending at the window edge is a protocol violation.
  • Every segment sent stays in the retransmit queue until an ACK covers it. ACKs are cumulative: one ACK can release several entries and slide the window forward.
  • RETRANSMIT the oldest held segment after its RTO expires. Early retransmits spend bandwidth on healthy links and turn the segment's ACK ambiguous; late ones stall the stream. Each retransmit doubles the RTO; the next clean sample cancels the backoff.
  • An ACK that covers a retransmitted segment carries ambiguous timing. Take the byte progress, skip the RTT sample (Karn's algorithm).

    Probe — duplicate segments and the byte stream

    If the sender's retransmit timer fires before the original ACK arrives, the segment is resent. The original might still be in transit, or might have arrived already with its ACK still traveling back. Either way, the receiver will see the same bytes twice. How does TCP prevent the duplicate from being delivered twice to the application?

    Answer the probe when ready, or ask about any field or build step before implementation. The build starts at step 32.1.

    What this completes

    Lesson 32 gives the TCP sender retained outbound bytes, an RTT estimate, and an RTO. The sender transmits several segments within the peer window and the fixed four-segment congestion limit. It retransmits the oldest segment when its ACK does not arrive before the RTO. The syscall accepts the portion that fits in the current window; connection teardown and a general socket API remain in Lesson 33.
