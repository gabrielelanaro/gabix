UDP: Deliver a Datagram to Port 5555

An IP address reaches mini-os. A port chooses who inside mini-os receives the message.

Concrete packet "hello" Protocol IPv4 number 17 Primary source RFC 768

Lesson 24 contacted one machine with ICMP echo. Lesson 25 delivers an application message to one endpoint inside that machine. UDP (User Datagram Protocol) contributes two ideas: ports select endpoints, and datagrams preserve message boundaries.

The missing address inside a host

Your Mac may run a browser, a DNS resolver, and a game simultaneously. Their packets can share one IP address because each endpoint uses a port number. The pair IP address : port names one network endpoint.

127.0.0.1:5555Your Mac sends five bytes to QEMU’s forwarded host port.
10.0.2.15:5555QEMU delivers that UDP datagram to the mini-os guest.
port 5555mini-os chooses the Lesson 25 echo handler.
“hello”The handler receives one five-byte payload and sends those bytes back.

The sender also chooses a source port, commonly an ephemeral short-lived port such as 53000. The echo handler reverses the endpoint pair: its reply travels from 10.0.2.15:5555 to the sender’s IP address and port 53000.

Every 16-bit field uses network byte order: most-significant byte first.
Source port · bytes 0–1

The sender’s return endpoint. RFC 768 permits zero when no reply address is needed. Our echo packet requires a real source port.

Destination port · bytes 2–3

The receive endpoint. Lesson 25 recognizes 5555 and leaves other ports without a handler.

Length · bytes 4–5

The total UDP size: eight header bytes plus all payload bytes. The smallest valid value is 8.

Checksum · bytes 6–7

A 16-bit Internet checksum over endpoint information, this header, and the payload.

Payload · byte 8 onward

The application’s complete message. UDP leaves its interpretation to the endpoint selected by the destination port.

How the receiver knows where the payload ends

IPv4 has already bounded the bytes handed to UDP. UDP reads its own length field and applies two checks before exposing a payload.

payload length = UDP length − 8

For "hello", UDP length is 8 + 5 = 13. The parser accepts it only when 8 ≤ UDP length ≤ IPv4 payload length. This rule prevents a short header and prevents UDP from reading beyond the enclosing IPv4 packet. Ethernet padding remains outside IPv4’s declared boundary.

Packet decoder · step 1 of 5

1 · IPv4 reaches the guest

Destination 10.0.2.15 selects mini-os. IPv4 total length supplies a bounded payload, and protocol 17 sends that payload to UDP.

2 · UDP validates its frame

The UDP length is 13. It fits inside the IPv4 payload and leaves exactly five bytes after the eight-byte header.

3 · The port selects code

Destination port 5555 selects the kernel echo handler. Lesson 26 will replace this fixed decision with a socket table.

4 · The handler receives one message

The payload slice is b"hello". Its five-byte boundary is preserved as one UDP datagram.

5 · The reply reverses endpoints

Source and destination IP addresses and ports swap roles. A fresh IPv4 header and UDP checksum carry "hello" back to the sender.

The checksum borrows the IP endpoints

UDP checksum input begins with a twelve-byte pseudo-header. These values participate in the calculation without becoming part of the UDP datagram’s transmitted bytes.

pseudo-header · source IP + destination IP + zero + protocol 17 + UDP length
UDP bytes on the wire · source port + destination port + length + zeroed checksum + payload
odd-byte padding · add one zero byte for calculation only when the combined UDP bytes have odd length

The pseudo-header binds the datagram to its IPv4 source, destination, protocol, and declared size. A packet delivered under the wrong IP endpoints should fail UDP validation. The implementation reuses Lesson 23’s RFC 1071 one’s-complement checksum routine over the assembled checksum inputs.

The contract UDP gives us

Each send creates one datagram, and each successful receive returns one datagram. UDP can lose, duplicate, or reorder datagrams. It provides no handshake and no retry. The Lesson 25 echo proof therefore asks one focused question: did one valid datagram addressed to port 5555 return with the same payload?

Retrieval check. IPv4 gives UDP 17 bounded bytes. The UDP length field says 13. How many payload bytes belong to this datagram?
