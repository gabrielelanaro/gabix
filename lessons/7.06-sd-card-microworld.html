What exactly is the clock?

A clock is a repeating electrical high/low signal. Its transitions provide timing for communication. Here the controller generates an SD clock on the CLK connection to the card. The data travels on a separate connection.

25 MHz means 25 million complete clock cycles per second. The driver sets a divider in a hardware register; clock logic then generates the repeating signal. The CPU’s own instruction clock is a separate clock.

Where are the RAM address and sector number used?

The function receives two different kinds of information:

fn write_sector(&mut self, sector: u64, data: &[u8; 512])
    -> Result<(), BlockError>

data refers to the source bytes in RAM. For an SDHC/SDXC card, sector becomes the command argument. The controller receives that sector number and CMD24. The CPU then copies the data into the controller’s FIFO, a hardware buffer whose oldest queued word is consumed first.

write32(ARGUMENT, argument);        // Destination on the card.
// ... send CMD24 and wait for buffer-write-ready ...
for bytes in data.chunks_exact(4) {
    write32(BUFFER_DATA,
        u32::from_le_bytes(bytes.try_into().unwrap()));
}

The source RAM pointer is used by the CPU while evaluating bytes. The driver never gives that pointer to this controller. This is programmed I/O (PIO). A read reverses the direction: the CPU repeatedly reads the DATA register and copies each word into a RAM array.

Source: write path · read path. SDSC cards use a byte address as the command argument; the driver multiplies the sector by 512 for them.

Does wait mean the CPU keeps polling?

Yes, in this Pi SD driver. The CPU repeatedly reads a controller status register until the required flag is set or the one-second deadline expires. It continues executing the polling loop during this wait.

loop {
    let status = read32(INTERRUPT_STATUS);
    // Check error bits, then the requested completion flag.
    // Check the elapsed-time deadline.
    core::hint::spin_loop();
}

The register is named INTERRUPT_STATUS, and its flags can be inspected by polling. Initialization writes zero to SIGNAL_ENABLE, so this driver uses no SD-completion interrupt handler. The controller’s transfer and clock logic continue while the CPU checks the flags.

Source: interrupt signaling disabled · idle/status polling. Excerpt above omits branches to make the repeated read visible.

ARM and registers: what does a register write do physically?

The Pi maps device registers into the CPU’s address space. A load or store to one of these addresses accesses controller state. This is memory-mapped I/O (MMIO).

Pi physical addressMeaning here
0x3f30002cClock-control bits, including the encoded divider.
0x3f300020DATA register: access the controller’s FIFO.
0x3f300030Status flags: check completion or error.

These illustrative ARM instructions show the kinds of accesses used by the Rust volatile helpers. Compiler register allocation varies.

strh r1, [r0]   // Store 16 bits: r0 points to clock control.
str  r3, [r2]   // Store 32 bits: r2 points to DATA.
ldr  r5, [r4]   // Read 32 bits: r4 points to status.

r0 through r5 are CPU registers holding addresses or values. The controller registers live in the device. For divider 4, the driver encodes the divider as 0x0400; enabling the internal and SD clocks adds the appropriate control bits. The CPU performs those configuration stores, and the clock logic generates subsequent pulses.

Source: base address and register offsets · clock encoding · volatile helpers. Controller definitions: BCM2835 peripherals §5, CONTROL1, DATA, INTERRUPT.

How does this compare with VirtIO on x86 and ARM?

The shared job is transferring a block between storage and RAM. The device interface determines how the driver submits the work. Completion handling is another choice.

Current gabix pathHow the bytes moveHow the CPU waits
Physical Pi · SDCPU copies words between RAM and the DATA FIFO.Spin-polls controller flags.
ARM QEMU virt · VirtIODescriptors give the device RAM buffer addresses.Spin-polls the used-ring index.
x86 QEMU · VirtIODescriptors give the device RAM buffer addresses.Checks the used ring; enables interrupts and halts while waiting.

A VirtIO descriptor contains a buffer address, length, and flags. The virtual device can access those buffers through the emulated device mechanism. The used ring records completed requests. SD PIO and VirtIO therefore expose different transfer mechanisms; polling versus interrupt wakeup is a separate distinction.

Source: ARM descriptors and polling · x86 descriptors and interrupt-enabled halt. The x86 path rechecks completion after waking, including a possible timer wake.
