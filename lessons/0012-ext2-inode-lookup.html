The lookup flow — inode number to struct

Reading inode 2 walks four structures in order. Each step takes the previous step's output as input:

Superblock (block 1)
gives us s_inodes_per_group = 128, s_inode_size = 128, block_size = 1024

BGDT (block 2)
descriptor 0 says bg_inode_table = 5

Inode table (block 5)

The math in one line: inode_byte = bg_inode_table × block_size + (N - 1) × s_inode_size. Five steps to go from a number to a parsed struct on disk.

The lookup chain — five steps from number to struct

To read inode N, the kernel walks four on-disk structures in order:

1
Superblock — tells us s_inodes_per_group and s_inode_size.
From Lesson 10. We parsed most fields but didn't expose these two yet — Lesson 12 adds them.
2
Block Group Descriptor Table (BGDT) — right after the superblock. One 32-byte entry per block group.
Tells us where each group's inode table lives. For our 1 MB disk there's one block group, so just one entry we care about.
3
Block group descriptor — specifically its bg_inode_table field: the block number where the inode table starts.
For our disk: bg_inode_table = 5 (mkfs puts the inode table at block 5).
4
Inode table — array of inode structs. Index into it: (N - 1) % s_inodes_per_group.
Inode numbers are 1-based. Index 0 in the table = inode 1 (the reserved "bad blocks" file). Index 1 = inode 2 (root directory).
5
Inode struct — 128 bytes (default s_inode_size). Parse the fields, return.
Includes i_mode (file type + permissions), i_size, i_block[15] (data block pointers), etc.

The arithmetic to compute the byte offset of inode N: 

// Block group containing inode N (0-indexed math, but inode numbers are 1-indexed)
group      = (N - 1) / s_inodes_per_group

// Index within that group's inode table
local_idx  = (N - 1) % s_inodes_per_group

// Byte offset on disk
inode_byte = bg_inode_table[group] * block_size + local_idx * s_inode_size

For inode 2 on our disk: group = 0, local_idx = 1, bg_inode_table[0] = 5, block_size = 1024, s_inode_size = 128. Byte offset = 5 × 1024 + 1 × 128 = 5248 = sector 10 byte 160. We'll read sectors 10 and 11 (1024 bytes total), index at byte 160, parse 128 bytes.

The block group descriptor (32 bytes)

One entry per block group. We only need three fields: where the inode table starts, and the free counts (for future allocation-aware logic).

Block group descriptor 32 bytes total
bg_block_bitmap u32 · 4 B 0x00
bg_inode_bitmap u32 · 4 B 0x04
bg_inode_table u32 · 4 B 0x08
bg_free_blocks u16 · 2 B 0x0C
bg_free_inodes u16 · 2 B 0x0E
bg_used_dirs u16 · 2 B 0x10
(padding + reserved) 14 B 0x12–0x1F
bg_block_bitmap u32

Block number where this group's block bitmap lives. The bitmap is one bit per data block in the group — 1 = used, 0 = free. We don't need this for Lesson 12 (just looking up existing inodes), but it's how the kernel allocates new blocks for file writes.

bg_inode_bitmap u32

Same idea for inodes. One bit per inode in the table.

bg_inode_table u32

The load-bearing field for Lesson 12. Block number where this group's inode table starts. For our disk: block 5.

inode 2 byte offset: bg_inode_table[0] × block_size + 1 × s_inode_size = 5 × 1024 + 1 × 128 = 5248
bg_free_blocks_count / bg_free_inodes_count u16

Per-group free counts. Should sum to the superblock's global free counts across all groups.

bg_used_dirs_count u16

Number of directories in this group. Used by the allocator to spread directories across groups (locality optimization).

The BGDT lives right after the superblock. For a 1024-byte block filesystem, that's block 2 (superblock is block 1). For our single-group disk, the table has just one entry — 32 bytes used of a 1024-byte block.

The on-disk inode struct (128 bytes)

Every file, directory, symlink, etc. has one. The struct holds the file's metadata plus 15 block pointers (12 direct + 1 indirect + 1 double-indirect + 1 triple-indirect). For Lesson 12 we parse just the metadata; reading file data via the block pointers comes in Lesson 13.

Decoding i_mode — file type + permissions

i_mode packs two things into 16 bits. The top 4 bits encode the file type; the bottom 12 bits are standard Unix permissions (the same bits chmod manipulates).

0x8000 S_IFREG Regular file
0x4000 S_IFDIR Directory ← inode 2 is this
0xA000 S_IFLNK Symbolic link
0x6000 S_IFBLK Block device (e.g., /dev/sda)
0x2000 S_IFCHR Character device (e.g., /dev/tty)
0x1000 S_IFIFO Named pipe (FIFO)
0xC000 S_IFSOCK Socket

The bottom 12 bits: standard rwxrwxrwx + setuid + setgid + sticky. We mostly ignore permissions in mini-os, but checking the type is essential — a directory entry's target inode must be S_IFDIR for us to walk into it.

Build steps — your turn

Five substeps. By the end we'll have looked up inode 2 (root directory) and parsed its 128-byte struct.

12.1Extend Superblock with the two extra fields

Lesson 10's Superblock is missing two fields we'll need: s_inodes_per_group (u32 @ offset 40) and s_inode_size (u16 @ offset 88). Add them.

For our disk: s_inodes_per_group = 128 (matches total inodes since we have one group), s_inode_size = 128 bytes.

12.2BlockGroupDescriptor struct + parser

Same pattern as Superblock: struct holding the fields we care about (block_bitmap, inode_bitmap, inode_table, free_blocks_count, free_inodes_count, used_dirs_count). Parse from 32 bytes via from_le_bytes.

12.3read_block_group_descriptor function

Read the BGDT for block group 0. For 1024-byte block filesystems, the BGDT is at block 2 (superblock is block 1). Read sectors 4 and 5, parse the first 32 bytes as a BlockGroupDescriptor.

Returns the descriptor. The inode_table field is what we use next.

12.4Inode struct + parser + read_inode

Inode struct with the fields we care about: mode (u16), size (u32), blocks (u32), block_pointers ([u32; 15]). Parser via from_le_bytes at standard offsets.

read_inode(dev, sb, bgd, n) — the arithmetic: inode_byte = bgd.inode_table × block_size + (n - 1) × sb.inode_size. Read the right sectors, index into them, parse 128 bytes.

12.5Verify inode 2 is the root directory

In main.rs, after the Lesson 10 superblock test:

  • Read block group descriptor 0
  • Read inode 2 via the new read_inode
  • Assert mode & 0xF000 == 0x4000 (S_IFDIR)
  • Print size, blocks, first few block_pointers
  • Verify block_pointers[0] != 0 — directory has at least one data block

For our disk: inode 2 should be a directory of size 1024 (one block), with block_pointers[0] pointing at the block containing the root directory entries. We'll parse those entries in Lesson 13.

Exact block_pointers[0] will depend on mkfs layout — for a 1 MB disk it's typically 8 (block 8 holds the root directory entries). What matters: mode has S_IFDIR set, size is non-zero, first block pointer is non-zero.

Pause and think

ext2 inodes are 128 bytes by default, but s_inode_size can be larger (256, 512, ...) on filesystems formatted for newer revisions. The first 128 bytes are always the standard struct; bytes 128+ are "extra space" used for things like extended attributes. Why keep the first 128 bytes fixed even when there's more space available?
