Lesson 14 · M5 · ext2 phase — VFS becomes filesystem-agnostic

Mount ext2 via Filesystem Trait

Define a Filesystem trait. ext2 implements it. VFS becomes generic — could mount a RAM disk alongside, plug in FAT later, etc.

Read time ~25 min Build time ~35–50 min Prereq Lesson 13

Lessons 10–13 built the ext2 reading layer. Lesson 14 plugs it into VFS via a Filesystem trait — the same abstraction Linux uses (struct super_operations, struct inode_operations, struct file_operations). The VFS layer stops knowing about ext2 specifically; it just calls trait methods. ext2 provides the implementation. Future filesystems implement the same trait.

The trait

A filesystem is anything that can answer these four questions: 

pub trait Filesystem {
    /// What kind of thing is inode N? File, dir, or doesn't exist?
    fn inode_kind(&self, ino: u64) -> Option<InodeKind>;

    /// Find a child by name in a directory. Returns child's inode number.
    fn lookup(&self, dir_ino: u64, name: &str) -> Option<u64>;

    /// List a directory's entries: (name, inode_number) pairs.
    /// Used for caching translated dirents at the VFS layer.
    fn list_dir(&self, dir_ino: u64) -> Option<Vec<(String, u64)>>;

    /// Read a file's bytes.
    fn read_file(&self, ino: u64) -> Option<Vec<u8>>;
}

That's it. Anything that can answer those four questions is a filesystem the VFS can mount. The trait lives in fs.rs; fs.rs has no knowledge of ext2.

The mounted-filesystem slot

One global holds the currently-mounted filesystem: 

lazy_static! {
    pub static ref MOUNTED_FS: Mutex<Option<Box<dyn Filesystem>>> = Mutex::new(None);
}

pub fn mount(fs: Box<dyn Filesystem>) {
    *MOUNTED_FS.lock() = Some(fs);
}

One filesystem at a time. (Linux supports many mounts simultaneously — we don't need that yet.)

The on-demand walk

resolve_path no longer walks an in-memory tree. It calls the trait:

1
Lock MOUNTED_FS, get the trait object. Start at ext2 inode 2 (root, by convention).
2
For each path component: check inode_kind(current_ino) == Dir, then call lookup(current_ino, component) to get the child's inode number.
3
At the leaf: check REGISTRY cache. On hit, return cached Arc<Inode>. On miss, build fresh.
4
Building fresh: for a directory, call list_dir and re-encode in fs.rs's dirent format (cached). For a file, call read_file and store the bytes.
5
Insert into REGISTRY keyed by inode number, return. Next call hits the cache.

The cache (REGISTRY) is the VFS layer's responsibility. The filesystem implementation just answers trait queries. Clean separation.

Ext2 as a struct, not free functions

Lesson 13's readers are free functions taking &mut VirtioBlk. Lesson 14 wraps them in a struct that owns the device + parsed superblock + BGD: 

pub struct Ext2 {
    dev: Mutex<VirtioBlk>,
    sb: Superblock,
    bgd0: BlockGroupDescriptor,
}

impl Ext2 {
    pub fn new(mut dev: VirtioBlk) -> Self {
        let sb = read_superblock(&mut dev);
        let bgd0 = read_block_group_descriptor(&mut dev, &sb, 0);
        Self { dev: Mutex::new(dev), sb, bgd0 }
    }
}

impl Filesystem for Ext2 {
    fn inode_kind(&self, ino: u64) -> Option<InodeKind> {
        let inode = self.read_inode(ino as u32)?;
        Some(if inode.is_dir() { InodeKind::Dir } else { InodeKind::File })
    }

    fn lookup(&self, dir_ino: u64, name: &str) -> Option<u64> {
        let dir = self.read_inode(dir_ino as u32)?;
        let entries = self.walk_directory(&dir);
        entries.iter().find(|e| e.name == name.as_bytes())
               .map(|e| e.inode as u64)
    }

    // ... list_dir, read_file similarly
}

The old free functions become methods on Ext2 (or private helpers called from them). Callers in main.rs build an Ext2, mount it, then VFS sees it as Box<dyn Filesystem>.

14.3Rewrite resolve_path for the trait

In src/fs.rs, replace the body of resolve_path: 

pub fn resolve_path(path: &str) -> Option<Arc<Inode>> {
    if !path.starts_with('/') { return None; }

    let fs_guard = MOUNTED_FS.lock();
    let fs = fs_guard.as_ref()?;

    let mut current_ino: u64 = 2;  // root by ext2 convention
    for component in path.split('/').filter(|c| !c.is_empty()) {
        let kind = fs.inode_kind(current_ino)?;
        if kind != InodeKind::Dir { return None; }
        current_ino = fs.lookup(current_ino, component)?;
    }

    // Cache check
    if let Some(cached) = REGISTRY.lock().get(&current_ino) {
        return Some(cached.clone());
    }

    // Cache miss: build fresh
    let kind = fs.inode_kind(current_ino)?;
    let data = match kind {
        InodeKind::Dir => {
            let entries = fs.list_dir(current_ino)?;
            let mut bytes = Vec::new();
            for (name, ino) in entries {
                bytes.extend(encode_dirent(&name, ino));
            }
            bytes
        }
        InodeKind::File => fs.read_file(current_ino)?,
    };

    let inode = Arc::new(Inode {
        ino: current_ino, kind, data: Mutex::new(data),
    });
    REGISTRY.lock().insert(current_ino, inode.clone());
    Some(inode)
}
14.4Mount at boot + verify

In src/main.rs, after the existing ext2 setup: 

// Move ownership of virtio_dev into Ext2 struct, then mount it
let ext2 = ext2::Ext2::new(virtio_dev);
let mounted: Box<dyn fs::Filesystem> = Box::new(ext2);
fs::mount(mounted);

// Verify
let hello = fs::resolve_path("/hello.txt").expect("should resolve");
let data = hello.data.lock();
assert_eq!(&data[..], b"hello from disk\n");

Also verify:

  • resolve_path("/") returns the root directory inode
  • resolve_path("/missing") returns None
  • Calling resolve_path("/hello.txt") twice: second call hits cache, no ext2 walk

Primary source

Linux's VFS layer is documented in Documentation/filesystems/vfs.html. The trait corresponds roughly to struct super_operations + struct inode_operations + struct file_operations (we collapse them into one for simplicity).

Each Linux filesystem implements these structs: ext2 in fs/ext2/super.c, ext4 in fs/ext4/, FAT in fs/fat/, etc. Adding a new filesystem doesn't require touching VFS code — same trait-based plug-in design we're using.
