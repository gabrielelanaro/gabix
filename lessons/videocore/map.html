How the Pi’s CPU talks to its GPU

When our Raspberry Pi draws a triangle, what work does the CPU do, and what happens inside the GPU? Start with the hardware blocks used by the triangle. The orange outline picks out one part at a time. The enlargement lets you read its label.

How does Gabix reach this hardware?

Before asking V3D to draw, we can ask it a smaller question. What number does it report as its identity? Step outside the diagram to see where that request begins.

A register is a small storage location or device interface with a hardware-defined meaning. V3D has one that reports its identity. Its number is already present before a triangle is drawn. Here is the line that asks for it.

Rust running on the ARM · v3d.rs, line 220

let id = read(V3D + IDENT0);

The read helper used above · v3d.rs, line 39

unsafe fn read(address: usize) -> u32 {
    read_volatile(address as *const u32)
}

Try it in your own words

Point to where read() executes, where its address leads, and where the ID comes from. Would the QPU need to run a color program for this read?

Compare explanations

The ARM executes read(). Its load reaches a register inside V3D. The ID comes from that register. The ARM can read that register as soon as V3D is accessible. The QPU has no shader work to do for an ID read.
