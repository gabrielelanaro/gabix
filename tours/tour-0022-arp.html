22.1Name the local addresses

File: src/net/mod.rs

QEMU user-mode networking gives the guest a fixed IP and gateway. Those addresses are protocol state, so they sit in the network module beside Ethernet and ARP.

src/net/mod.rsslirp constants
pub const OUR_IP: [u8; 4] = [10, 0, 2, 15];
pub const GATEWAY_IP: [u8; 4] = [10, 0, 2, 2];

22.2Parse the ARP packet

File: src/net/arp.rs

ArpPacket is the 28-byte RFC 826 shape as Rust fields. Multi-byte fields use big-endian conversion, matching Ethernet and IP header convention.

src/net/arp.rspacket shape
pub struct ArpPacket {
    htype: u16, ptype: u16,
    hlen: u8, plen: u8, oper: u16,
    sha: [u8; 6], spa: [u8; 4],
    tha: [u8; 6], tpa: [u8; 4],
}

The boot probe round-trips a request and reply through to_bytes and parse before any network I/O.

22.3Build requests and replies

File: src/net/arp.rs

The request asks for a target IP with an unknown target MAC. The reply rotates the request sender into the target fields and fills mini-os's own MAC/IP as the sender.

src/net/arp.rsbuilders
ArpPacket::request(our_mac, OUR_IP, GATEWAY_IP)
ArpPacket::reply_to(&request, our_mac, OUR_IP)

22.4Merge into the cache

File: src/net/arp.rs

The cache is a small BTreeMap protected by a spin mutex. Every valid ARP packet teaches the sender mapping: spa -> sha.

src/net/arp.rscache update
ARP_CACHE.lock().insert(packet.spa, packet.sha);

The first slirp reply stores 10.0.2.2 -> 52:55:0a:00:02:02.

22.5Resolve the gateway

File: src/virtio.rs

NetDevice::resolve_arp owns the wire work. It checks the cache, broadcasts on miss, polls RX, parses ARP replies, and returns the learned MAC.

serial outputresolver proof
[arp] cache miss: asking for 10.0.2.2
[arp] learned 10.0.2.2 -> 52:55:0a:00:02:02
[arp] 10.0.2.2 is at 52:55:0a:00:02:02
[arp] cache hit: 10.0.2.2 is at 52:55:0a:00:02:02

22.6Answer requests for us

File: src/virtio.rs

handle_arp_frame also handles inbound requests. When an ARP request targets 10.0.2.15, mini-os builds a reply and sends it to the asker's MAC.
