Lesson 13 makes the kernel read a directory's contents. The directory's data block contains a linked list of variable-length dirents — each one joins a name to an inode number. Walk the list, find the name you want, get its inode.

Easiest filesystem lesson yet. The hard ext2 concepts (superblock, BGDT, inode table) are done. Lesson 13 is just "walk a linked list inside a data block" — pure data-structure work.

13.1 + 13.2 Dirent struct + read_block helper

Files: src/ext2.rs

The Dirent struct is straightforward — 4 fixed fields plus a variable name:

src/ext2.rs— Dirent struct + parse_at
pub struct Dirent {
    pub inode:     u32,  // 0 = dead slot
    pub rec_len:   u16,  // bytes to next entry
    pub name_len:  u8,
    pub file_type: u8,   // EXT_FT_DIR, EXT_FT_REG_FILE, etc.
    pub name:      Vec<u8>,  // heap-allocated; no null terminator
}

pub fn parse_at(bytes: &[u8], offset: usize) -> (Dirent, usize) {
    // ... read header at offset, name at offset+8 ...
    (Dirent { ... }, offset + rec_len as usize)
}

Returns the next offset (offset + rec_len) so the walker doesn't have to recompute it. The linked-list traversal advance is built into the parser's return value.

read_block(dev, block_n) -> [u8; 1024] extracts the "read 2 sectors, concat" pattern that's been inline in read_superblock, read_inode, and now the directory walker. Top-level function — three callers all share it now.

13.3 + 13.4 walk_directory + lookup_in_dir

Files: src/ext2.rs

The walker is a linked-list traversal — parse, advance, repeat:

src/ext2.rs— walk_directory
pub fn walk_directory(dev: &mut VirtioBlk, dir_inode: &Inode) -> Vec<Dirent> {
    let mut entries = Vec::new();

    for (_, &block_n) in dir_inode.block_pointers.iter().take(12) {
        if block_n == 0 { continue; }  // sparse direct pointers

        let block = read_block(dev, block_n);
        let mut offset = 0;
        while offset + 8 <= block.len() {
            let (entry, next) = Dirent::parse_at(&block, offset);
            if entry.is_live() { entries.push(entry); }
            if next <= offset { break; }  // safety: rec_len=0 would loop
            offset = next;
        }
    }
    entries
}

lookup_in_dir wraps it for the path-resolution use case:

src/ext2.rs— lookup_in_dir
pub fn lookup_in_dir(dev, dir_inode, name: &[u8]) -> Option<u32> {
    for entry in walk_directory(dev, dir_inode) {
        if entry.name == name { return Some(entry.inode); }
    }
    None
}

13.5 Test: assert the 3 mkfs-default entries

Files: src/main.rs

The test verifies exactly what a fresh mkfs produces. Three entries, all directories, all pointing at the expected inodes:

src/main.rs— assertions on the walked entries
assert_eq!(entries.len(), 3, "expected 3 entries");

let dot = entries.iter().find(|e| e.name == b".").unwrap();
let dotdot = entries.iter().find(|e| e.name == b"..").unwrap();
let lf = entries.iter().find(|e| e.name == b"lost+found").unwrap();

assert_eq!(dot.inode, 2);      // . points at root
assert_eq!(dotdot.inode, 2);   // .. points at root too (root's parent is itself)
assert_eq!(lf.inode, 11);     // lost+found is inode 11 by convention
assert_eq!(lf.file_type, EXT_FT_DIR);

The "root's .. points at root" pattern eliminates a base case in path resolution — covered in the sidebar in learning-records 0015.
