The useful boundary in this implementation is hardirq versus task context. Interrupt handlers count, wake, and acknowledge. The deferred kernel task owns locks, drains descriptors, parses packets, and delivers datagrams. A timer wake provides reliable progress in QEMU while the programmed virtio-net MSI-X path remains available for further diagnosis.

host sendto(127.0.0.1:5555)
  → QEMU hostfwd → virtio RX used ring
  → timer or RX MSI-X wakes net-rx
  → network_task drains → Ethernet → IPv4 → UDP
  → socket::deliver queues bytes and wakes PID 0
  → recvfrom returns sender → ring-3 sendto
  → UDP → IPv4 → Ethernet + zero padding to 60 bytes
  → virtio TX → QEMU slirp → host recvfrom

29.1Queues receive dedicated MSI-X mappings

src/virtio.rs · src/interrupts.rs · src/apic.rs

virtio-net owns its own MSI-X table. RX queue 0 uses entry 0 and vector 0x30; TX queue 1 uses entry 1 and vector 0x31. These vectors sit above the PIC range 0x20–0x2f. Each naked wrapper preserves all general-purpose registers before calling a tiny Rust handler.

pub const VIRTIO_NET_RX_VECTOR: u8 = 0x30;
pub const VIRTIO_NET_TX_VECTOR: u8 = 0x31;

extern "C" fn virtio_net_rx_inner() {
    VIRTIO_NET_RX_INTERRUPTS.fetch_add(1, Ordering::Relaxed);
    if let Some(pid) = crate::virtio::net_task_pid() { crate::task::wake(pid); }
    crate::apic::end_of_interrupt();
}

29.2The deferred task blocks between drains

src/main.rs · src/virtio.rs · src/task.rs

main installs the device, spawns net-rx, and publishes its PID. The task disables interrupts around “drain until empty, then Blocked,” closing the empty-ring/lost-wakeup race. try_lock prevents a spinlock deadlock while interrupts are disabled.

loop {
    without_interrupts(|| {
        if try_with_net_device(|device| while device.poll_rx().is_some() {}).is_some() {
            crate::task::block_current();
        }
    });
    crate::task::yield_now();
}

29.3The timer is a bounded progress backstop

src/interrupts.rs

The current QEMU configuration accepts the queue-to-vector mappings but does not emit virtio-net MSI-X consistently. Every timer tick marks net-rx Ready. The scheduler runs a short empty drain when idle and processes an arriving frame within 10 ms at 100 Hz. Packet parsing remains outside the timer ISR.

if let Some(pid) = crate::virtio::net_task_pid() {
    crate::task::wake(pid);
}

29.4Delivery crosses from driver state to socket state

src/virtio.rs · src/net/socket.rs

poll_rx recycles the descriptor after copying bounded packet data. The dispatcher validates Ethernet, IPv4, and UDP, then calls socket::deliver. Delivery owns the payload in the socket queue, takes the receiver PID, releases the socket lock, and wakes the task.

crate::net::socket::deliver(
    udp_packet.header.dst_port,
    Endpoint { ip: udp_packet.ip_header.src_ip, port: udp_packet.header.src_port },
    udp_packet.payload(),
);

29.5Blocking receive publishes one atomic decision

src/syscall.rs · src/task.rs

block_current_if gives the socket the current PID and marks the same scheduler entry Blocked under one lock. Interrupts remain disabled through the deliberate yield, so a timer cannot preempt the syscall on its entry stack between publication and switching.

interrupts::disable();
let should_block = task::block_current_if(|pid| socket.register_waiter_if_empty(pid));
if should_block { task::yield_now(); } else { interrupts::enable(); }

29.6Ethernet padding makes short TX buffers valid

src/virtio.rs

The first diagnostic payload produced 14 Ethernet + 20 IPv4 + 8 UDP + 16 data = 58 bytes. QEMU's backend is given a 64-byte minimum TX buffer. The TX frame is zero-filled, so extending the descriptor length pads after the IP packet without changing IP or UDP lengths.

const ETHERNET_MIN_TX_BUFFER: usize = 64;
let tx_len = core::cmp::max(eth_frame.len(), ETHERNET_MIN_TX_BUFFER);
tx_queue.build_tx_chain(header_phys, 12, frame_phys, tx_len as u32);
Why does UDP checksum ignore the two padding bytes?

The IPv4 total-length and UDP length fields end before Ethernet padding. Receivers use those protocol lengths and discard bytes that remain in the Ethernet payload.
