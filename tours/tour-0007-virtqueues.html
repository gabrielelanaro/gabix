7.1 Allocate the three regions

Files: src/virtio.rs (new VirtQueue struct + VirtQueue::new), src/main.rs (test block)

The split virtqueue is three arrays in physically-contiguous, page-aligned RAM. We get page alignment for free by allocating one 4 KiB frame per region from the frame allocator — each frame is page-aligned and physically contiguous by construction.

src/virtio.rs — VirtQueue struct (the per-queue state) 
pub struct VirtQueue {
    queue_size: u16,

    // Frame numbers from the frame allocator.
    desc_frame: u64,
    avail_frame: u64,
    used_frame: u64,

    // Virtual addresses — kernel-side access via the direct map.
    desc_virt: u64,
    avail_virt: u64,
    used_virt: u64,

    // Physical addresses — what we tell the device.
    desc_phys: u64,
    avail_phys: u64,
    used_phys: u64,
}

For queue_size = 64, the three regions are 1024 B (descriptor table = 64 × 16), 134 B (available ring), and 518 B (used ring). Each fits comfortably in a single 4 KiB frame.

src/virtio.rs — VirtQueue::new: allocate, zero, return 
pub fn new(queue_size: u16) -> Self {
    let q = queue_size as usize;
    let desc_bytes = q * 16;
    let avail_bytes = 6 + q * 2;  // flags + idx + ring + used_event
    let used_bytes  = 6 + q * 8;  // flags + idx + ring entries + avail_event

    assert!(desc_bytes  <= 4096);
    assert!(avail_bytes <= 4096);
    assert!(used_bytes  <= 4096);

    let desc_frame  = crate::frame_allocator::allocate().expect("...");
    let avail_frame = crate::frame_allocator::allocate().expect("...");
    let used_frame  = crate::frame_allocator::allocate().expect("...");

    let offset = crate::memory::phys_offset();
    // ... compute phys and virt for each, zero the regions ...
}

7.2 Configure the queue in common config

Files: src/virtio.rs (new configure_queue, new u16/u64 MMIO helpers)

Now the kernel has three frames. It needs to tell the device where they live — by writing their physical addresses into the queue fields of the common config region. The order is fixed by the spec: select the queue, negotiate size, write the three addresses, then enable.

src/virtio.rs — VirtioBlk::configure_queue 
pub fn configure_queue(&self, queue: &VirtQueue) {
    // 1. Select queue 0 (request queue for virtio-blk)
    self.write_common_u16(COMMON_QUEUE_SELECT, 0);

    // 2. Negotiate size: read device max, write back ours
    let device_max = self.read_common_u16(COMMON_QUEUE_SIZE);
    assert!(queue.queue_size() <= device_max);
    self.write_common_u16(COMMON_QUEUE_SIZE, queue.queue_size());

    // 3-5. Region addresses (physical)
    self.write_common_u64(COMMON_QUEUE_DESC,  queue.desc_phys());
    self.write_common_u64(COMMON_QUEUE_AVAIL, queue.avail_phys());
    self.write_common_u64(COMMON_QUEUE_USED,  queue.used_phys());

    // 6. Enable (the commit bit)
    self.write_common_u16(COMMON_QUEUE_ENABLE, 1);

    // Verify acceptance
    let enable_readback = self.read_common_u16(COMMON_QUEUE_ENABLE);
    assert_eq!(enable_readback, 1);
}

The MMIO helpers (read_common_u16, write_common_u16, write_common_u64) are just read_volatile/write_volatile at common_virt + offset — same pattern as Lesson 6's u8 and u32 helpers. 

[test] configure virtqueue in common config (7.2)
[virtio] configuring virtqueue 0 in common config
[virtio]   device max queue_size: 256 (we want 64)
[virtio]   queue_enable readback: 1 (expect 1)
[virtio] virtqueue 0 active

Device max is 256 (QEMU's virtio-blk default). We negotiate down to 64 — smaller is fine for our purposes, and matches the "everything fits in one frame per region" assumption from 7.1. The read-back of queue_enable = 1 is the spec's acceptance signal.

7.3 Descriptor free list

Files: src/virtio.rs (free-list field, alloc/free methods, write_descriptor helper, VirtqDesc struct)

The descriptor table is a fixed-size array of queue_size entries. To use them, the kernel needs a way to claim an entry, fill it in, and later return it to the pool. A stack of free indices does the job in O(1) per operation, no fragmentation.

src/virtio.rs — Free list field, init, alloc/free 
// In VirtQueue struct:
free_list: alloc::vec::Vec<u16>,

// In new():
free_list: (0..queue_size).collect(),

// Methods:
pub fn alloc_descriptor(&mut self) -> Option<u16> {
    self.free_list.pop()
}

pub fn free_descriptor(&mut self, idx: u16) {
    self.free_list.push(idx);
}

The descriptor entry layout itself is spec-fixed — 16 bytes with fields at known offsets. We model it as a repr(C) struct so the compiler lays out the fields in declaration order with no padding.

src/virtio.rs — Descriptor layout (matches the byte-layout visual in the lesson) 
#[repr(C)]
struct VirtqDesc {
    addr:  u64,  // offset 0x00
    len:   u32,  // offset 0x08
    flags: u16,  // offset 0x0C
    next:  u16,  // offset 0x0E
}

const VIRTQ_DESC_F_NEXT:  u16 = 0x01;
const VIRTQ_DESC_F_WRITE: u16 = 0x02;

Test output confirms the LIFO behavior — pop from the high end, push returns to the high end.

7.4 Available ring submission (Release barrier)

Files: src/virtio.rs (new submit_chain)

Publishing a chain to the available ring is a three-step dance: read the current idx, write the head index into ring[idx % N], advance idx by one. The trick is the third step — advancing idx has to publish the second step (and any descriptor writes the caller did before submitting) atomically.

src/virtio.rs — submit_chain: load idx, write ring slot, fetch_add(1, Release) 
pub fn submit_chain(&self, head_index: u16) -> u16 {
    let q = self.queue_size as u64;

    // Pointer to avail->idx at offset 2 from region base.
    let idx_atomic: *const AtomicU16 =
        (self.avail_virt + 2) as *const AtomicU16;

    // Read current idx (Relaxed — no publication depends on this).
    let old_idx = unsafe { (*idx_atomic).load(Ordering::Relaxed) };

    // Write head index into ring[old_idx % N] at offset 4 + slot*2.
    let slot = (old_idx as u64) % q;
    let ring_entry_virt = self.avail_virt + 4 + slot * 2;
    unsafe {
        write_volatile(ring_entry_virt as *mut u16, head_index);
    }

    // Advance idx with Release. This is the memory barrier:
    // prior writes (the ring entry AND the descriptor fields)
    // become visible before the new idx is.
    let _new_idx = unsafe {
        (*idx_atomic).fetch_add(1, Ordering::Release)
    };

    old_idx
}
On x86, fetch_add(1, Release) often compiles down to a single locked instruction that's already fully ordered — the barrier is essentially free. On ARM it emits a dmb ish before the store. Either way, the source code says what it means.

7.5 Used ring polling + kick

Files: src/virtio.rs (extended cap parsing for notify_off_multiplier, notify_virt in VirtioBlk, kick, poll_completion)

Two pieces: a way to wake the device when there's new work, and a way to observe when work has been completed.

Kick writes the queue index (0) to a notification register inside the notification capability region. The address is notify_cap_base + queue_notify_off × multiplier, where queue_notify_off is per-queue (read from common config) and the multiplier is a constant from the notification capability body.

src/virtio.rs — VirtioBlk::kick 
pub fn kick(&self) {
    let queue_notify_off =
        self.read_common_u16(COMMON_QUEUE_NOTIFY_OFF) as u64;
    let off = queue_notify_off * (self.notify_off_multiplier as u64);
    let notify_addr = self.notify_virt + off;

    unsafe {
        write_volatile(notify_addr as *mut u16, 0);
    }
}

Poll reads used->idx with Acquire ordering — pairs with the device's Release-ordered store on completion. If idx advanced past last_used_idx, a new completion is ready in ring[last_used_idx % N].

src/virtio.rs — VirtQueue::poll_completion 
pub fn poll_completion(&mut self) -> Option<(u32, u32)> {
    let q = self.queue_size as u64;

    let idx_atomic: *const AtomicU16 =
        (self.used_virt + 2) as *const AtomicU16;

    // Acquire pairs with the device's Release store on completion.
    let current = unsafe { (*idx_atomic).load(Ordering::Acquire) };

    if current == self.last_used_idx {
        return None;
    }

    // Read entry at last_used_idx % N. Layout: 4 bytes in, each entry 8.
    let slot = (self.last_used_idx as u64) % q;
    let entry_virt = self.used_virt + 4 + slot * 8;
    let (id, len) = unsafe {
        (
            read_volatile(entry_virt as *const u32),
            read_volatile((entry_virt + 4) as *const u32),
        )
    };

    self.last_used_idx = self.last_used_idx.wrapping_add(1);
    Some((id, len))
}

Supporting kick meant extending the cap parsing — the notification capability has an extra field at offset 16 that the others don't:

// word4 at offset 16 — only meaningful for the notification cap.

let notify_off_multiplier = word4;
