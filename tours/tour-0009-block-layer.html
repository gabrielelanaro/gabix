9.1 Refactor: VirtioBlk owns VirtQueue

Files: src/virtio.rs (VirtioBlk struct + new methods), src/main.rs (use new API)

Previously virtio_dev and queue were separate locals in main.rs. For read_block to work, it needs both. The clean fix: VirtioBlk owns the queue.

src/virtio.rs — new field on VirtioBlk 
pub struct VirtioBlk {
    bus: u8,
    device: u8,
    func: u8,
    common_virt: u64,
    notify_virt: u64,
    notify_off_multiplier: u32,
    queue: Option<VirtQueue>,  // ← new
}
src/virtio.rs — setup_queue + queue_mut 
pub fn setup_queue(&mut self, queue_size: u16) {
    let queue = VirtQueue::new(queue_size);
    self.configure_queue(&queue);
    self.queue = Some(queue);
}

pub fn queue_mut(&mut self) -> &mut VirtQueue {
    self.queue.as_mut().expect("queue not set up")
}

Boot sequence in main.rs shrinks:

src/main.rs — old vs new 
// Old (L7-L8):
let queue = VirtQueue::new(64);
virtio_dev.configure_queue(&queue);
// ... queue stays as a local in main

// New (L9):
virtio_dev.setup_queue(64);
// ... queue is inside virtio_dev, accessed via queue_mut() if needed

9.2 Add read_block

Files: src/virtio.rs (new method, build_read_chain signature change)

The full Lesson 8 dance, hidden behind one function:

src/virtio.rs — read_block: 9 lines of mechanism 
pub fn read_block(&mut self, sector: u64) -> [u8; 512] {
    let buffers = BlkBuffers::new();
    let req = VirtioBlkReq::new_read(sector);
    buffers.write_header(&req);

    let (head, mid, tail) = self.queue.as_mut().unwrap()
        .build_read_chain(buffers.header_phys, buffers.data_phys, buffers.status_phys);

    self.queue.as_mut().unwrap().submit_chain(head);
    self.kick();

    let _completion = (0..200_000)
        .find_map(|_| self.queue.as_mut().unwrap().poll_completion())
        .expect("read_block: no completion");

    assert_eq!(buffers.read_status(), VIRTIO_BLK_S_OK);

    let queue = self.queue.as_mut().unwrap();
    queue.free_descriptor(head);
    queue.free_descriptor(mid);
    queue.free_descriptor(tail);

    let mut block = [0u8; 512];
    block.copy_from_slice(&buffers.read_data_prefix(512));
    block
}

Borrow checker note: each self.queue.as_mut().unwrap() is a separate statement rather than a single let queue = ... binding. The binding would lock the borrow for the whole function and conflict with self.kick(). Each chained call releases the borrow at the end of the statement.

build_read_chain signature change: now returns (head, mid, tail) instead of just head. Necessary so the caller can free all three descriptors. Callers that only need head use let (head, _, _).

src/virtio.rs — build_read_chain returns all 3 indices 
pub fn build_read_chain(
    &mut self,
    header_phys: u64,
    data_phys: u64,
    status_phys: u64,
) -> (u16, u16, u16) {  // was: u16
    // ... allocate 3, write_descriptor 3 times ...
    (head, mid, tail)
}

9.3 Verify: read multiple sectors

Files: src/main.rs (3 read_block calls + assertions)

Three calls, three arrays. Sector 0 has the disk signature; sectors 1 and 2 are all zero (no filesystem yet — ext2's superblock will go to sector 2 in Lesson 11):

src/main.rs — the test block 
let block0 = virtio_dev.read_block(0);
assert_eq!(&block0[0..15], b"MINIOS_DISK_v0\n");
assert_eq!(block0[15..].iter().filter(|&&b| b == 0).count(), 497);

let block1 = virtio_dev.read_block(1);
assert_eq!(block1.iter().filter(|&&b| b == 0).count(), 512);

let block2 = virtio_dev.read_block(2);
assert_eq!(block2.iter().filter(|&&b| b == 0).count(), 512);
