Code Tour — First Disk Read (Keystone 1)

From empty DMA buffers to verified disk bytes. Five steps, each one a separate commit, each one verified on QEMU.

Steps done 8.1 – 8.5 (complete) Commits 233f4dd → d42e82a

Lesson 8 is the payoff for everything in Lessons 5–7. We built PCI enumeration (5), the virtio handshake (6), and virtqueue mechanics (7). Now we use those primitives to send a real virtio-blk read request and verify the bytes match MINIOS_DISK_v0 — the signature we wrote to sector 0 back in Lesson 5's make-disk.sh.

A note on what made this lesson harder than expected: the Lesson 7 test had submitted a descriptor with bogus data (addr=0, len=0, flags=0). QEMU's virtio-blk rejected it in a way that blocked the entire queue — Lesson 8's subsequent real request never got processed until we removed that bogus submission. Captured in step 8.4 below.

8.1 virtio-blk request header struct

Files: src/virtio.rs (new struct, new constants), src/main.rs (size assertion)

The 16-byte request header is what tells the device what to do with the buffers the descriptors point at. Layout: operation type, reserved (zero), starting sector.

src/virtio.rs — VirtioBlkReq + operation/status constants 
const VIRTIO_BLK_T_IN:    u32 = 0;  // read
const VIRTIO_BLK_T_OUT:   u32 = 1;  // write
const VIRTIO_BLK_T_FLUSH: u32 = 4;  // flush

const VIRTIO_BLK_S_OK:     u8 = 0;
const VIRTIO_BLK_S_IOERR:  u8 = 1;
const VIRTIO_BLK_S_UNSUPP: u8 = 2;

#[repr(C)]
#[derive(Debug, Clone, Copy)]
pub struct VirtioBlkReq {
    pub type_:    u32,  // offset 0x00 — operation code
    pub reserved: u32,  // offset 0x04 — spec says zero
    pub sector:   u64,  // offset 0x08 — starting sector
}

impl VirtioBlkReq {
    pub fn new_read(sector: u64) -> Self {
        Self { type_: VIRTIO_BLK_T_IN, reserved: 0, sector }
    }
}

Verified the layout is exactly 16 bytes at boot — catches future regressions if anyone adds a field:

[virtio]   size = 16 bytes (expect 16)
[virtio]   align = 8 bytes

8.2 BlkBuffers — DMA-able buffer bundle

Files: src/virtio.rs (new struct), src/main.rs (allocate)

The device needs physical addresses for header / data / status. The frame allocator gives us page-aligned frames with trivially computable physical addresses. We take one frame each — wasteful but simple:

src/virtio.rs — BlkBuffers::new allocates 3 frames, zeroes them 
pub fn new() -> Self {
    let header_frame = crate::frame_allocator::allocate().expect("...");
    let data_frame   = crate::frame_allocator::allocate().expect("...");
    let status_frame = crate::frame_allocator::allocate().expect("...");

    let offset = crate::memory::phys_offset();
    let header_phys = header_frame * 4096;
    // ... compute data_phys, status_phys, three virt addresses

    // Zero everything
    unsafe {
        core::ptr::write_bytes(header_virt as *mut u8, 0, 4096);
        // ... data and status same
    }
    // ... return Self { ... }
}

Plus three accessors: write_header(&VirtioBlkReq) (writes the struct into the header buffer), read_status() -> u8 (read the 1-byte status after completion), read_data_prefix(n) -> Vec<u8> (snapshot first N bytes of the data buffer).

8.3 Build the 3-descriptor read chain

Files: src/virtio.rs (new method on VirtQueue), src/main.rs (write header + build chain)

The chain pattern is fixed: header (F_NEXT, device reads), data (F_NEXT | F_WRITE, device writes for read), status (F_WRITE only, tail of chain).

src/virtio.rs — VirtQueue::build_read_chain 
pub fn build_read_chain(
    &mut self,
    header_phys: u64,
    data_phys:   u64,
    status_phys: u64,
) -> u16 {
    let head = self.alloc_descriptor().expect("...");
    let mid  = self.alloc_descriptor().expect("...");
    let tail = self.alloc_descriptor().expect("...");

    self.write_descriptor(head, header_phys, 16,
        VIRTQ_DESC_F_NEXT, mid);
    self.write_descriptor(mid, data_phys, 512,
        VIRTQ_DESC_F_NEXT | VIRTQ_DESC_F_WRITE, tail);
    self.write_descriptor(tail, status_phys, 1,
        VIRTQ_DESC_F_WRITE, 0);

    head
}

Caller writes the request header into the header buffer first:

src/main.rs — set up the header content + build the chain 
let req = virtio::VirtioBlkReq::new_read(0);  // type=IN, sector=0
buffers.write_header(&req);

let head = queue.build_read_chain(
    buffers.header_phys,
    buffers.data_phys,
    buffers.status_phys,
);

8.4 + 8.5 Submit, kick, poll; verify bytes

Files: src/virtio.rs (added debug_state diagnostic), src/main.rs (kick + poll loop, verification)

The submit + kick + poll sequence reuses Lesson 7's helpers directly. The Lesson 8 part is the polling loop with a generous cap and the post-completion verification.

src/main.rs — submit, kick, poll up to 200000 times 
let (a, u, l) = queue.debug_state();
println!("pre-submit: avail={} used={} last={}", a, u, l);

queue.submit_chain(head);
virtio_dev.kick();

let mut completion = None;
for iters in 0..200_000 {
    if let Some(c) = queue.poll_completion() {
        println!("completion after {} iters", iters + 1);
        completion = Some(c);
        break;
    }
}
let (_id, _len) = completion.expect("no completion");

First attempt failed: used->idx stayed at 0 through all 200000 iterations. Diagnostic showed the device wasn't responding at all. 

pre-submit state: avail->idx=1 used->idx=0 last_used=0
kick: wrote queue 0 to notify register
post-poll state: avail->idx=2 used->idx=0 last_used=0
no completion arrived — read failed

Root cause: Lesson 7's step 7.4 had submitted a descriptor with addr=0, len=0, flags=0. QEMU's virtio-blk rejected it in a way that blocked the entire queue. Lesson 8's real request sat behind it forever.

Fix: Lesson 7's test no longer submits garbage. It still verifies alloc_descriptor / write_descriptor / free_descriptor work — just doesn't push anything into the avail ring. Lesson 8 sends the first real submission. 

After removing Lesson 7's bogus submission:
[test] submit + kick + poll (8.4)
[virtio] pre-submit state: avail->idx=0 used->idx=0 last_used=0
[virtio] kick: wrote queue 0 to notify register at virt 0x180FE003000
[virtio] poll_completion: used->idx 0 -> 1, id=63 len=513
[virtio]   completion arrived after 1 poll iters

The completion reports id=63 (matches our head descriptor index) and len=513. That's 512 (data buffer, F_WRITE) + 1 (status byte, F_WRITE) — the total bytes the device wrote to device-writable descriptors.

Step 8.5 verification: read the status byte, snapshot the data buffer, compare against expected values.

src/main.rs — verify status byte + data signature 
let status = buffers.read_status();
assert_eq!(status, virtio::VIRTIO_BLK_S_OK as u8);

let data = buffers.read_data_prefix(16);
assert_eq!(&data[0..15], b"MINIOS_DISK_v0\n");

let tail = buffers.read_data_prefix(512);
let tail_zeros: usize = tail[15..].iter().filter(|&&b| b == 0).count();
assert_eq!(tail_zeros, 497);

// Free the 3 descriptors back to the free list
queue.free_descriptor(63);
queue.free_descriptor(62);
queue.free_descriptor(61);
