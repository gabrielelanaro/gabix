TCP passive open, echo, and teardown

Route an inbound SYN to a listener, return an accepted stream descriptor, and close both byte directions with FIN.

Core src/net/tcp.rsSyscalls src/syscall.rsProof tests/test_tcp_echo.sh

A host program cannot connect to mini-os until the kernel can associate an inbound SYN with a listening port. Lesson 33 adds TCP socket descriptors, listener and connection tables, blocking accept and read, stream writes, and the passive side of the FIN exchange. A ring-3 server on port 8080 proves the path through QEMU's TCP forwarding.

33.1A TCP descriptor identifies one socket object

FdTable stores Arc<TcpSocket> beside regular files and UDP sockets. Forked processes can share the same socket object because the table's shallow clone copies the Arc.

src/fs.rs— descriptor object variants
pub enum OpenObject {
    File(Arc<File>),
    Socket(Arc<UdpSocket>),
    TcpSocket(Arc<TcpSocket>),
}

33.2The listener and connection tables route inbound segments

LISTENERS maps a destination port to its socket. CONNECTIONS maps the four endpoint fields to a connection. An inbound SYN creates a connection in SYN_RCVD and sends SYN-ACK. The final ACK changes that connection to ESTABLISHED, appends it to the listener's completed queue, and wakes the task blocked in accept.

src/net/tcp.rs— receive demultiplexing keys
static ref LISTENERS: IrqMutex<BTreeMap<u16, Weak<TcpSocket>>>;
static ref CONNECTIONS:
    IrqMutex<BTreeMap<ConnectionKey, Arc<TcpSocket>>>;

33.3Blocking calls publish a waiter before yielding

accept removes the next completed connection and assigns it a descriptor. An empty queue stores the current process identifier before the scheduler switches tasks. The final handshake ACK calls wake for that identifier.

src/syscall.rs— blocking accept loop
loop {
    if let Some(connection) = listener.pop_accepted() {
        return with_current_fd_table(
            |table| table.open_tcp_socket(connection));
    }
    block_current_if(|pid| listener.register_accept_waiter(pid));
    yield_now();
}

The TCP read path applies the same sequence to its receive queue. It returns zero after FIN arrives and all queued bytes have been copied to user memory.

33.4FIN closes one byte direction

An inbound FIN increments recv_next by one, marks end-of-file, sends an ACK, and changes an established server connection to CLOSE_WAIT. The application can still write bytes in this state. Closing the descriptor builds FIN-ACK at send_next, increments send_next, and enters LAST_ACK. The peer's ACK changes the state to CLOSED.

src/net/tcp.rs— passive close state changes
Established + receive FIN  → CloseWait
CloseWait   + close()      → LastAck
LastAck     + receive ACK  → Closed

33.5The host-forwarded test crosses every layer

The fixture binds port 8080, listens, accepts one connection, reads a byte slice, writes the same slice, reads end-of-file, and closes. The host Python client connects to 127.0.0.1:8080. QEMU forwards that connection to 10.0.2.15:8080.

Current boundary

The server table can represent several four-tuples, and one ring-3 process serves one connection in the proof. The active-open Lesson 31 client still uses its earlier single global control block. TIME_WAIT expiry, retransmitted FIN handling, half-open backlog accounting, concurrent fork-per-connection service, and accepted peer-address output remain future work.
