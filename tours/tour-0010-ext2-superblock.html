Code Tour — ext2 Superblock

From raw disk sectors to a parsed filesystem header. Four commits, each verified via the printed superblock fields.

Steps done 10.1 – 10.4 (complete) Commits f7cc83e → 34a7e78

Lesson 10 is the start of the filesystem phase. We tell mkfs.ext2 to format the disk image as a real ext2 filesystem, then teach the kernel to read the first structure (the superblock) and verify it's actually ext2.

The disk doesn't know it's ext2. Bytes are bytes. ext2 is a parsing convention the kernel applies to those bytes. Lesson 10 installs that convention — at least the first 1024 bytes of it.

10.1 Format the disk image as ext2

Files: scripts/make-disk.sh (mkfs.ext2 step added)

The old script just created a sparse 1 MB file and wrote MINIOS_DISK_v0\n at offset 0. The new script adds a mkfs.ext2 -F disk.img call to format the file as a real ext2 filesystem. The signature is gone — Lesson 10 verifies the ext2 magic instead.

macOS doesn't ship mkfs.ext2. The script tries multiple paths (command -v, brew location, /usr/sbin fallback) so it works on both macOS with brew install e2fsprogs and on Linux directly.

scripts/make-disk.sh — the format step 
truncate -s "${SIZE_MB}M" "$DISK_IMG"
"$MKFS_EXT2" -F "$DISK_IMG"

# Verify: bytes at offset 1080 should be 53 EF (ext2 magic in LE)
dd if="$DISK_IMG" bs=1 skip=1080 count=2 2>/dev/null | hexdump -C
$ ./scripts/make-disk.sh
Creating filesystem with 1024 1k blocks and 128 inodes
Writing superblocks and filesystem accounting information: done
Created disk.img (1 MB, ext2)
ext2 magic at offset 1080 (should be 53 EF):
00000000  53 ef                                             |S.|

Magic bytes 53 ef at offset 1080 = 0xEF53 in little-endian. Disk is now ext2.

10.2 Superblock struct + parser

Files: src/ext2.rs (new module), src/main.rs (declare module)

The Superblock struct holds 10 fields — the ones we need for inode lookup and directory walking in upcoming lessons. The full on-disk struct is 1024 bytes with dozens of fields; we ignore the rest (quota stuff, journal hints, etc.).

src/ext2.rs — Superblock struct 
pub struct Superblock {
    pub inodes_count:       u32,
    pub blocks_count:       u32,
    pub r_blocks_count:     u32,
    pub free_blocks_count:  u32,
    pub free_inodes_count:  u32,
    pub first_data_block:   u32,
    pub block_size:          u32,  // 1024 << s_log_block_size
    pub magic:               u16,
    pub state:               u16,
}

Parser uses from_le_bytes at each field's spec offset. Closure helpers hide the try_into().unwrap() boilerplate:

src/ext2.rs — parse(): bytewise read at spec offsets 
pub fn parse(bytes: &[u8]) -> Self {
    let u32_at = |off: usize| -> u32 {
        u32::from_le_bytes(bytes[off..off+4].try_into().unwrap())
    };
    let u16_at = |off: usize| -> u16 {
        u16::from_le_bytes(bytes[off..off+2].try_into().unwrap())
    };

    let s_log_block_size = u32_at(24);
    Self {
        inodes_count:       u32_at(0),
        blocks_count:       u32_at(4),
        // ...
        block_size: 1024 << s_log_block_size,
        magic:      u16_at(56),
        state:      u16_at(58),
    }
}

Why from_le_bytes instead of repr(C) transmute:

  • No alignment assumption. The byte slice doesn't need 4-byte alignment.
  • Explicit endianness documentation. Code says "this is LE" via the function name.
  • Portable. Same code works on big-endian architectures — from_le_bytes handles the conversion.
  • No unsafe. Pure safe Rust.

10.3 + 10.4 Read superblock from disk + verify

Files: src/ext2.rs (read_superblock function), src/main.rs (test block)

The superblock is 1024 bytes; read_sector returns 512. Read two sectors, concat, parse:

src/ext2.rs — read_superblock 
pub fn read_superblock(dev: &mut VirtioBlk) -> Superblock {
    let sector2 = dev.read_sector(2);
    let sector3 = dev.read_sector(3);

    let mut bytes = [0u8; 1024];
    bytes[.. 512].copy_from_slice(&sector2);
    bytes[512..].copy_from_slice(&sector3);

    Superblock::parse(&bytes)
}

Test block in main.rs:

src/main.rs — the Lesson 10 test 
let sb = ext2::read_superblock(&mut virtio_dev);
sb.print();

assert!(sb.is_ext2(), "ext2 magic not found");
assert_eq!(sb.block_size, 1024);
assert_eq!(sb.first_data_block, 1);
assert_eq!(sb.state, 1, "filesystem should be clean");
assert!(sb.inodes_count > 0 && sb.inodes_count < 1000);
assert!(sb.blocks_count > 0 && sb.blocks_count < 10000);

Bug along the way: my first cut read s_state as u32, which slurped in the next field (s_errors) too — got 65537 instead of 1. Fixed by reading as u16 per the ext2 spec.
