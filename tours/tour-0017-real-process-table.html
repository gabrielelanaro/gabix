Code Tour — Real Process Table

The scheduler keeps runnable register frames. The process table owns stable PIDs, parent/child links, exit status, address spaces, and file descriptors.

Commit 39f2612 Verified fork smoke + hello smoke

Lesson 17 is a structural cleanup after fork, exec, and wait already work. The goal is to make PID identity survive future reaping. Scheduler vector indices can change once tasks are removed; process IDs need a separate owner.

The invariant: once the kernel has handed out PID N, the process table never hands out PID N again. A removed process leaves a retired slot.

17.1Add the process table module

File: src/process.rs

Pid becomes a newtype instead of a raw u64. Process owns process identity and resources. ProcessTable owns allocation and lookup.

src/process.rsstable PID allocation
pub struct Pid(pub u64);

pub struct ProcessName {
    bytes: [u8; PROCESS_NAME_MAX],
    len: usize,
}

pub struct Process {
    pub pid: Pid,
    pub parent: Option<Pid>,
    pub children: Vec<Pid>,
    pub exit_status: Option<i64>,
    pub name: ProcessName,
    pub address_space: AddressSpace,
    pub fd_table: FdTable,
}

ProcessTable::allocate writes into a Vec<Option<Process>> indexed by PID. next_pid only increases. remove takes a process out of its slot and leaves that PID retired.

17.2Trim Task to scheduler state

File: src/task.rs

Task now describes how to resume execution: saved context, kernel stack, entry function, scheduler state, and the per-task ring-3 entry stack. Its only process link is pid.

src/task.rsscheduler-side task shape
pub struct Task {
    pub pid: Pid,
    pub state: TaskState,
    pub context: TaskContext,
    pub stack_top: u64,
    pub entry_fn: unsafe extern "C" fn(),
    pub entry_stack_top: u64,
}

The rename from syscall_stack_top to entry_stack_top matches the hardware role: syscalls use it, and ring-3 timer interrupts use the same stack via TSS.RSP0.

17.3Fork allocates Process first, Task second

File: src/task.rs

spawn_fork_child needs the child PID before it can place stacks. The function allocates a child process with a temporary address space, computes PID-based stack locations, deep-clones the real address space, writes it back into the process table, then pushes the scheduler task.

src/task.rsordering inside spawn_fork_child
let pid = {
    let mut table = PROCESS_TABLE.lock();
    table.allocate(Process::new(
        "fork-child",
        Some(parent_pid),
        memory::AddressSpace::from_current(),
        crate::fs::FdTable::new(),
    ))
};

let id = pid.as_u64();
// map child kernel stack + entry stack using id

let mut address_space = crate::memory::AddressSpace::new();
address_space.deep_clone_from_current();

let mut table = PROCESS_TABLE.lock();
table.get_mut(pid).unwrap().address_space = address_space;
table.get_mut(parent_pid).unwrap().children.push(pid);

Stack placement still uses the PID value, so the byte layout remains identical while PIDs and scheduler indices match. Lesson 18 can break that assumption deliberately during reaping.

17.4Accessors read ProcessTable after dropping Scheduler

Files: src/task.rs, src/syscall.rs

Public helpers now grab the current PID from SCHEDULER, drop that lock, then look up process state in PROCESS_TABLE. The whole operation still runs with interrupts disabled.

src/task.rsfd-table access pattern
pub fn with_current_fd_table<F, R>(f: F) -> R
where
    F: FnOnce(&mut crate::fs::FdTable) -> R,
{
    x86_64::instructions::interrupts::without_interrupts(|| {
        let pid = {
            let sched = SCHEDULER.lock();
            sched.tasks[sched.current].pid
        };
        let mut table = PROCESS_TABLE.lock();
        f(&mut table.get_mut(pid).unwrap().fd_table)
    })
}

sys_getpid, sys_fork, and sys_wait4 convert Pid back to u64 only at the syscall ABI boundary.

17.5Wait reaps the process table slot

File: src/task.rs

wait_for_zombie_child now snapshots zombie task PIDs, finds the child relationship in PROCESS_TABLE, removes the child process slot, then marks the scheduler task dead.

src/task.rswait result now carries Pid
pub enum WaitResult {
    Reaped { child_pid: Pid, exit_status: i64 },
    NoChildren,
    WouldBlock,
}

The scheduler task remains as a dead entry for now. That is Lesson 18's job: remove dead tasks and free process-owned resources cleanly.
