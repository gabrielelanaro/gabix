23.2Compute the internet checksum

File: src/net/checksum.rs

IPv4 protects its header with the internet checksum. The helper reads bytes as big-endian 16-bit words, folds overflow back into the low 16 bits, handles an odd trailing byte, then inverts the folded sum.

src/net/checksum.rsfull helper
pub fn internet_checksum(data: &[u8]) -> u16 {
    let mut sum = 0u32;
    let mut i = 0;

    while i + 1 < data.len() {
        sum += u16::from_be_bytes([data[i], data[i + 1]]) as u32;
        sum = fold_carry_once(sum);
        i += 2;
    }

    if i < data.len() {
        sum += ((data[i] as u16) << 8) as u32;
    }

    while sum > 0xffff {
        sum = fold_carry_once(sum);
    }

    !(sum as u16)
}

fn fold_carry_once(sum: u32) -> u32 {
    (sum & 0xffff) + (sum >> 16)
}

The important verification trick: after a checksum has been written into a header, running the same helper over the header returns 0. The helper returns the inverted sum, so a correct header inverts to zero.

23.4Parse and validate an inbound header

File: src/net/ipv4.rs

Ipv4Header::parse receives the whole IPv4 packet: header plus payload. It returns early on malformed input. Each early return is a small gate that keeps later code simple.

src/net/ipv4.rsvalidation gates
if packet.len() < IPV4_HEADER_LEN {
    return None;
}

let version = packet[0] >> 4;
let ihl = packet[0] & 0x0f;
if version != 4 || ihl != 5 {
    return None;
}

let total_len = u16::from_be_bytes([packet[2], packet[3]]);
if total_len < IPV4_HEADER_LEN as u16 || total_len as usize > packet.len() {
    return None;
}

if checksum::internet_checksum(&packet[..IPV4_HEADER_LEN]) != 0 {
    return None;
}

The fragment check is deliberately strict for this lesson. A packet with More Fragments set, or a non-zero fragment offset, is left for a later reassembly lesson.

    return None;

    return None;
}

23.5Build the outbound IPv4 header

File: src/net/ipv4.rs

Ipv4Header::build creates exactly 20 bytes. The checksum field is zero while the checksum is computed, then bytes 10 and 11 receive the result.

src/net/ipv4.rsheader builder
let mut header = [0u8; IPV4_HEADER_LEN];
header[0] = VERSION_IHL_NO_OPTIONS;
header[1] = 0;
header[2..4].copy_from_slice(&(total_len as u16).to_be_bytes());
header[4..6].copy_from_slice(&0u16.to_be_bytes());
header[6..8].copy_from_slice(&FLAG_DONT_FRAGMENT.to_be_bytes());
header[8] = DEFAULT_TTL;
header[9] = protocol;
header[10..12].copy_from_slice(&0u16.to_be_bytes());
header[12..16].copy_from_slice(&src_ip);
header[16..20].copy_from_slice(&dst_ip);

let checksum = checksum::internet_checksum(&header);
header[10..12].copy_from_slice(&checksum.to_be_bytes());

payload_len is a small convenience for logs and future protocol dispatch: total length minus the fixed header length.

23.6Send IPv4 through the real device path

File: src/virtio.rs

send_ipv4_packet is the main Lesson 23 integration point. It builds the IP header, chooses the next hop, resolves that hop through ARP, wraps the IP packet in an Ethernet frame, and calls the existing send_frame.

src/virtio.rsTX integration
pub fn send_ipv4_packet(
    &mut self,
    protocol: u8,
    dst_ip: [u8; 4],
    payload: &[u8],
) -> Option<()> {
    assert!(payload.len() <= ETHERNET_MTU - IPV4_HEADER_LEN);

    let next_hop_ip = next_hop_for(dst_ip);
    let next_hop_mac = self.resolve_arp(next_hop_ip)?;
    let ip_header = Ipv4Header::build(protocol, net::OUR_IP, dst_ip, payload.len());

    let ethernet_header = EthernetHeader {
        dst: next_hop_mac,
        src: self.mac(),
        ethertype: ETHERTYPE_IPV4,
    };

    let frame_len = ETHERNET_HEADER_LEN + IPV4_HEADER_LEN + payload.len();
    let mut frame = [0u8; ETHERNET_HEADER_LEN + ETHERNET_MTU];
    frame[0..ETHERNET_HEADER_LEN].copy_from_slice(&ethernet_header.to_bytes());
    frame[ETHERNET_HEADER_LEN..ETHERNET_HEADER_LEN + IPV4_HEADER_LEN]
        .copy_from_slice(&ip_header);
    frame[ETHERNET_HEADER_LEN + IPV4_HEADER_LEN..frame_len].copy_from_slice(payload);

    self.send_frame(&frame[..frame_len]);
    Some(())
}

23.7Choose the next hop

File: src/virtio.rs

next_hop_for is tiny routing logic. For another 10.0.2.x address, mini-os can ask ARP for that destination directly. For any other network, mini-os sends the Ethernet frame to the slirp gateway.

src/virtio.rsfirst routing rule
fn next_hop_for(dst_ip: [u8; 4]) -> [u8; 4] {
    if dst_ip[0] == net::OUR_IP[0]
        && dst_ip[1] == net::OUR_IP[1]
        && dst_ip[2] == net::OUR_IP[2]
    {
        dst_ip
    } else {
        net::GATEWAY_IP
    }
}

23.8Dispatch received frames centrally

File: src/virtio.rs

poll_rx is the receive entry point. It reads one completed RX descriptor, dispatches the Ethernet frame, and returns an event the caller can match on.

src/virtio.rsRX event and dispatcher
pub enum NetRxEvent {
    Arp(ArpPacket),
    Ipv4(Ipv4Header),
    Other,
}

pub fn poll_rx(&mut self) -> Option<NetRxEvent> {
    let frame = self.recv_frame()?;
    Some(self.dispatch_frame(&frame))
}

fn dispatch_frame(&mut self, frame: &Frame) -> NetRxEvent {
    if let Some(packet) = self.handle_arp_frame(frame) {
        return NetRxEvent::Arp(packet);
    }

    if let Some(header) = self.handle_ipv4_frame(frame) {
        return NetRxEvent::Ipv4(header);
    }

    NetRxEvent::Other
}
src/virtio.rsIPv4 handler
pub fn handle_ipv4_frame(&mut self, frame: &Frame) -> Option<Ipv4Header> {
    if frame.ethertype != ETHERTYPE_IPV4 {
        return None;
    }

    let header = Ipv4Header::parse(&frame.payload[..frame.payload_len])?;
    if header.dst_ip != net::OUR_IP {
        println!("[ip] dropped frame for {}.{}.{}.{}",
            header.dst_ip[0], header.dst_ip[1], header.dst_ip[2], header.dst_ip[3]);
        return None;
    }

    println!("[ip] rx proto={} src={}.{}.{}.{} dst={}.{}.{}.{} len={}",
        header.protocol,
        header.src_ip[0], header.src_ip[1], header.src_ip[2], header.src_ip[3],
        header.dst_ip[0], header.dst_ip[1], header.dst_ip[2], header.dst_ip[3],
        header.total_len);

    Some(header)
}

23.10Let a user program request TX and RX

Files: src/syscall.rs, tests/fixtures/net_smoke.rs, scripts/make-disk.sh

The network smoke fixture is a normal ring-3 ELF on the ext2 disk. It prints a marker, calls a TX syscall, prints another marker, then calls an RX-wait syscall. The kernel keeps ownership of the virtio-net driver; the user program chooses when the proof starts.

23.11Drive real QEMU packets from the test

File: tests/test_net_smoke.sh

The shell test starts QEMU in the background and waits for the user-triggered RX marker. After that marker appears, the host sends UDP datagrams to 127.0.0.1:5555. QEMU forwards them to the guest, virtio-net receives an Ethernet frame, and the IPv4 dispatcher parses the packet.
