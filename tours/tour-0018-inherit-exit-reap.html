Code Tour - Inherit, Exit, Reap

A guided pass through the small pieces that make forked files, exit cleanup, and wait-by-PID work together.

Files src/fs.rs, src/task.rs, src/syscall.rs Test tests/test_inherit_wait.sh

Lesson 18 is about ownership. A forked child receives handles to the same open files as its parent. When a process exits, it releases those handles. When a parent waits, it reads the exit code and removes the finished child from the process table.

18.1Copy the FD table shape

File: src/fs.rs

FdTable::clone_shallow creates a fresh table with the same slot numbers. Each slot points at the same File object through an Arc. That shared File holds the cursor, so parent and child advance one read position.

src/fs.rsshared File handles
pub fn clone_shallow(&self) -> Self {
    Self {
        table: self.table.clone(),
    }
}

Cloning an Arc<File> bumps a counter. The file object stays alive until every process drops its handle.

18.2Give the child inherited files

File: src/task.rs

spawn_fork_child already builds the child process. It now reads the parent process, clones the parent's FD table, and passes that table into Process::new.

src/task.rsfork child process setup
let child_fd_table = table
    .get(parent_pid)
    .expect("spawn_fork_child: parent process missing")
    .fd_table
    .clone_shallow();

let proc = Process::new(
    "fork-child",
    Some(parent_pid),
    memory::AddressSpace::from_current(),
    child_fd_table,
);

The child still gets its own address space and stacks. File handles are the shared part here.

18.3Close files during exit

File: src/task.rs

mark_current_zombie sets the exit code and replaces the process FD table with an empty table. The old table drops after the process-table lock is released.

src/task.rsrelease open descriptors
let closed_fds = proc.fd_table.open_count();
let old_fd_table = core::mem::replace(
    &mut proc.fd_table,
    FdTable::new(),
);

drop(old_fd_table);

The zombie keeps the small pieces the parent needs: PID, parent link, and exit status. Open files leave at exit time.

18.4Wait for one child or any child

Files: src/syscall.rs, src/task.rs

The syscall layer reads two arguments: target PID in rdi, status pointer in rsi. u64::MAX means any child. A positive PID means that exact child.

src/task.rswait target
pub enum WaitTarget {
    Any,
    Specific(Pid),
}

wait_for_zombie_child searches only children that match the target. If the target child still exists and has not exited yet, the parent blocks. If the target child is gone or never belonged to the parent, the syscall returns -1.

Where to Ask Questions

Good follow-ups: why the cursor is shared, why exit closes files before wait reaps the child, or why wait(pid) must ignore other exited children.
