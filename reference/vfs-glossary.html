Core VFS abstractions

VFS (Virtual File System)

The kernel layer between user syscalls (open, read, write, close) and filesystem-specific code (ext4, tmpfs, procfs). Dispatches each syscall to the right backend via function-pointer tables on the file and inode objects.

Avoid "filesystem" — a VFS is the dispatch layer; a filesystem is what gets dispatched to.

Superblock

A mounted filesystem instance. Holds global info (block size, free space, root inode pointer) and the operations table for this filesystem. One per mount.

Inode (Index Node)

A file's identity. Holds metadata (size, owner uid, group gid, permissions, timestamps, link count, allocated block count) and a way to fetch the data. Has no name; multiple dentries can point at one inode.

Avoid "file" — a file is what an inode represents; the inode is the metadata object.

Dentry (Directory Entry)

A name → inode link. Lives in the parent directory. Forms the directory tree. Multiple dentries can point at the same inode (hard links).

Avoid "filename" — filename is the user-visible string; dentry is the kernel object.

File (struct file)

An open instance of an inode. Holds the cursor (offset), access mode (read/write), and a reference to the underlying inode. Private per open() call; shared across fork() and dup().

File Descriptor (FD)

A per-process integer index into the FD table. Maps to a struct file. Always non-negative; 0/1/2 are reserved by convention for stdin/stdout/stderr.

Lifecycle fields

Link Count (i_nlink)

The number of dentries pointing at an inode. Persisted on disk. When it reaches 0, the inode's data blocks can be freed (subject to the reference count also being 0).

Reference Count (i_count)

The number of open struct file instances pointing at an inode. In-memory only (not persisted). When it reaches 0, the kernel can drop the in-memory inode (subject to the link count also being 0 for freeing data blocks).

Hard Link

A second dentry pointing at an existing inode. Created by ln source target. Both names refer to the same data; the inode's link count goes up by one. Deleting one name does not delete the data; only when the last dentry is removed does the inode become a candidate for freeing.

atime / mtime / ctime

The three timestamps in an inode. atime = access time (updated on read). mtime = modify time (updated on write to the data). ctime = change time (updated on any inode metadata change — chmod, chown, rename).

FD-table operations

dup

Duplicate an FD. Returns a new FD number pointing at the same struct file as the original. Both FDs share the cursor and access mode. dup2(old, new) lets you specify the target FD number — used by shells for redirection (>, 2>&1) and pipelines (|).

Avoid "copy" — the FD number is new; the underlying File is shared, not copied.

Memory layering

Earned during Lesson 2 sidebar on "where does file data live?" — stack, heap, and frame allocator are different granularities over the same physical RAM, not separate pools.

Frame allocator

The lowest-level allocator — manages all of physical RAM as 4 KB frames. Returns frame numbers (not pointers); caller maps the frame to a virtual address to use it. mini-os's is a bitmap; Linux's analog is the buddy page allocator.

Heap (kernel heap)

Sub-page allocator layered on top of the frame allocator. mini-os's is linked_list_allocator wrapped in #[global_allocator], managing a fixed 100 KB region (itself backed by 25 frames from the frame allocator). Linux's analog is the slab allocator (kmalloc).

Avoid "the heap" as synonym for "memory" — heap is one consumer of frames, not a separate pool.

#[global_allocator]

Rust attribute that registers a static as the allocator for all Box, Vec, String, Arc, etc. in the crate. In mini-os this is ALLOCATOR: LockedHeap in src/allocator.rs. Without this attribute and an init(start, size) call, Box::new panics.

Direct map (physical_memory_offset)

A virtual address range where every byte of physical RAM is reachable linearly: virt_addr = direct_map_base + phys_addr. mini-os's PHYS_OFFSET (set from boot_info.physical_memory_offset, currently 0x180_0000_0000) is the direct-map base. Used by phys_to_virt() to reach physical frames (e.g., page tables) from kernel code without setting up a translation.

Page cache

In Linux, the kernel's cache of recently-accessed file pages in RAM. Indexed by (inode, page_offset) in an address_space per inode. For ramfs, the page cache IS the storage (no disk backup). For disk-backed filesystems, the page cache is a window over the disk — pages get loaded on read miss, flushed on writeback.

Avoid "the page cache is the heap" — different allocators. Page cache uses the buddy page allocator; heap (slab) is for small kernel objects.

Syscall / user-kernel boundary

USER_ADDR_LIMIT

Constant in mini-os (0x0000_8000_0000_0000, 2^47 — first non-canonical address). Any pointer at or above this is in the kernel upper half or the non-canonical hole. Used by is_user_range() to validate syscall arguments.

is_user_range(ptr, len)

mini-os helper that returns true if [ptr, ptr+len) is entirely within user space. Used by every syscall taking a user pointer (sys_read, sys_write) to reject kernel-pointer attacks. Returns u64::MAX (EFAULT sentinel) on failure. Does NOT catch in-range-but-unmapped pointers — that requires a page-fault handler.

Pending — not yet promoted

You have been exposed to these but have not yet demonstrated understanding. They graduate into the sections above once you do.

Superblock operations table (sb_ops) — the function-pointer table on a superblock.
File operations table (fops) — the function-pointer table on File/Inode that VFS dispatches through.
Dentry cache (dcache) — in-memory cache of resolved paths.
ramfs — the simplest Linux filesystem, all in memory, no disk.
address_space — Linux's per-inode structure holding the page cache tree. Roughly HashMap plus operations for the filesystem to populate/evict pages.
Buddy allocator — Linux's analog of our frame allocator; allocates 2^order pages.
Slab allocator — Linux's analog of our heap; sub-page allocs via object pools.
phys_to_virt() — mini-os helper that adds PHYS_OFFSET to a physical address.
ioctl — Input/Output Control syscall for device-specific operations beyond read/write.
TTY (TeleTYpewriter) — terminal device abstraction.
ptrace — process-trace primitive used by debuggers; can rewrite FDs of a running process.
TIOCSTI — Terminal I/O Control Simulate Terminal Input; pushes bytes into TTY input queue.
